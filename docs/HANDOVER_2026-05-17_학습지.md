## §2. 핵심 수학 — 단계별 설명

### 2.1 6D state representation

우리 정책은 *pursuer body frame* 에서 6D state 사용:

```
x = (Δx, Δy, Δh, Δψ, V_p, V_e)
```

- **Δx (ft)**: pursuer 좌표계에서 적의 *우측* 위치. Δx>0 = 적이 오른쪽.
- **Δy (ft)**: pursuer 좌표계에서 적의 *전방* 위치. Δy>0 = 적이 우리 앞.
- **Δh (ft)**: alt 차이. Δh>0 = 적이 위.
- **Δψ (rad)**: heading 차이. Δψ=0 = 같은 방향, Δψ=π = 반대 방향.
- **V_p (kts)**: 우리 속도 (pursuer velocity)
- **V_e (kts)**: 적 속도 (evader velocity)

**왜 이 6 변수?**
- *상대 위치* 3 (Δx, Δy, Δh) — 적과의 기하 관계 충분 표현
- *heading 차이* (Δψ) — 두 기체의 방향 관계
- *양쪽 속도* (V_p, V_e) — 동역학 + capture 조건 평가
- *roll, pitch 등 미사용* — point-mass 근사 (small-angle γ 가정)

### 2.2 파생 obs — ATA, AA, HCA

3 핵심 각도:

| 약어 | full name | 정의 (수식) | 직관 |
|---|---|---|---|
| **ATA** | Antenna Train Angle | atan2(\|Δx\|, Δy) | 우리 nose ↔ 적 위치 각. **ATA=0 = 적이 정면** |
| **AA** | Aspect Angle | 적 nose ↔ 우리 위치 각 | **AA=0 = 우리가 적 6시 (stern), AA=180 = head-on** |
| **HCA** | Heading Crossing Angle | \|Δψ\| (mod 180°) | 두 기체 *진행 방향* 차이. **HCA=0 = 같은 방향 (parallel chase)** |

**사격 (WEZ) 조건**:
- ATA < 12° (우리가 적을 *정조준*)
- 500 < dist < 3000 ft (사거리)
- closure > 0 (적이 다가오는 중)

**의미**: ATA 는 *우리의 사격 의지*. AA 는 *적이 우리를 보는 각도*. HCA 는 *둘이 같은 방향 가는지*.

### 2.3 V 함수 (Lyapunov-style score)

PLAN §2.6.3 에서 정의된 **BFM mode 별 V_i**. 각 V_i 는 *해당 mode 의 이상적 상태* 로부터의 *거리* — *작을수록 좋음*. (Hamilton-Jacobi value function 의 형태)

#### V_PN (Pure Pursuit + WEZ approach)
```
V_PN = ½·ATA² + ½·λ_d·(dist - d_WEZ*)² + ½·λ_V·(V_p - V_target)²
```
- 항 1: ATA 작게 (정렬)
- 항 2: dist 가 WEZ 중심 거리 d_WEZ* 에 (=1750ft, sweet spot)
- 항 3: V_p 가 V_target 매칭
- λ_d = 1/(1250)² ≈ 6.4×10⁻⁷ (WEZ width 정규화)
- λ_V = 1/V_REF² (V_REF=100 kts)
- V_target(dist) = V_e + (V_SPRINT - V_e) · clip((dist-WEZ_OUTER)/SPRINT_SCALE) — *dist-adaptive*

#### V_corner (Corner speed tracking)
```
V_corner = ½·(V_p - V_c)² / V_REF²
```
- V_c (corner speed) ≈ 438 kts @ 15000ft — *최대 instantaneous turn rate* 속도
- V_p < V_c → 가속
- V_p > V_c → 감속
- *순간 turn rate 최대화*

#### V_1circle (1-circle BFM — R-min 추적)
```
V_1circle = ½·λ_R·(R(V_p) - R_min)² + ½·σ_1c(HCA)·ATA²
```
- R(V_p) = V_p² / (g · n_z_max) — 우리 *순간 turn radius*
- R_min = 최소 가능 turn radius (V_corner 에서 달성)
- σ_1c(HCA) = HCA<90° 일 때 활성 (1-circle regime)
- "내가 적보다 *더 작은 원* 으로 turn → 적의 inside 점거"

#### V_corner_2c (2-circle BFM — *외*-원 traversal)
```
V_corner_2c = ½·(V_p - V_c)² + σ_2c(HCA)·ATA² + dist 항
```
- HCA > 120° (서로 마주봄) 시 활성
- 양쪽이 *반대 방향 큰 원* 그리며 *재 merge* 시도

#### V_LDT (Lag Displacement Turn — Shaw 1985)
```
V_LDT = ½·(ATA - ATA_lag*)² + dist 항
```
- ATA_lag* = ±90° (적의 옆) — *intentional miss* 로 변위 누적
- overshoot 회피 + 적 뒤 잡기

#### V_yoyo (high/low yo-yo — 수직 BFM)
```
V_yoyo = ½·(Δh - Δh_target)² + ½·ATA²
```
- high yo-yo: Δh<0 (우리 아래) → climb 로 PE 축적 후 dive 로 KE 변환
- low yo-yo: Δh>0 → dive 로 가속 후 climb 로 정렬

#### V_T (capture-time)
```
V_T = ½·((dist - d_WEZ*)/d_REF)² · exp(-closure / V_REF)
```
- closure-aware: closure 좋으면 V_T 작음 (가까이)
- closure 나쁘면 (음수) V_T 폭증 (멀어짐 페널티)
- **closure 가 V_p·cos(ATA) + V_e·cos(AA) 의 함수** → ω 채널 transmission 비영 (H1 lemma 회피)

### 2.4 ∇V (gradient) — 정책의 *방향 신호*

각 V_i 의 6D gradient (closed-form 미리 유도):
```
∇V_PN = (∂V/∂Δx, ∂V/∂Δy, ∂V/∂Δh, ∂V/∂Δψ, ∂V/∂V_p, ∂V/∂V_e)
```

**검증 (G1 gate)**: `_finite_diff_grad(V_func, x, h=1e-3)` 와 closed-form ∇V 의 max_rel_err ≤ 0.0002% 일치. 코드: `tools/basis/gradient_approximators.py:635-`.

### 2.5 B_d (dynamics control matrix)

F-16 6D dynamics 가 *control-affine*:

```
dx/dt = f0(x) + B_d(x) · u_p + B_c(x) · u_e
```

- u_p = (ω, γ̇, a) — 우리 control: (turn rate rad/s, climb rate rad/s, accel kts/s)
- u_e = 동일 형태 (적 control)

**B_d 의 ω 채널 row** (우리 turn 의 state 영향):
```
B_d[:,0] = (Δy, -Δx, 0, -1, 0, 0)
```
- Δy: turn 시 적이 우리 우측으로 이동 (Δy 변화)
- -Δx: turn 시 적이 우리 후방 (Δx 변화)
- -1: turn 시 우리 heading 변화 (Δψ)

**B_d 의 γ̇ 채널 row** (수직):
```
B_d[:,1] = (0, -V_p_fps, 0, 0, 0, 0)  -- alt 차원만 영향
```

**B_d 의 a 채널 row** (가속):
```
B_d[:,2] = (0, 0, 0, 0, 1, 0)  -- V_p 만 영향
```

### 2.6 Optimal Control (PMP / HJ)

Hamilton-Jacobi optimal control:
```
u* = arg min_u { (∇V)ᵀ · (f0 + B_d·u) }
   = arg min_u { (B_dᵀ·∇V)ᵀ · u }   (f0 무관)
```

**Bang-bang form**:
```
u* = -sign(B_dᵀ · ∇V) · u_max
```

**Smooth saturation** (실용):
```
BtG = B_dᵀ · ∇V             # 3-dim (ω-ch, γ̇-ch, a-ch)
gain = u_max / BTG_SCALE
u_star = clip(-BtG · gain, -u_max, +u_max)
```

- `BTG_SCALE` = 각 채널의 *typical magnitude* (정규화 상수)
- `u_max` = (ω_max, γ̇_max, accel_max) — F-16 envelope 한계

**의미**: u* 의 부호는 *V 줄이는 방향*. magnitude 는 *BtG 크기* 에 비례 (작은 신호 = 약한 명령).

### 2.7 H1 Lemma — V_dist 의 ω 채널 transmission ≡ 0 (Z3 PROVED)

**Lemma 명세**:
```
V_dist = ½·λ_d·(dist - d*)²,  dist = √(Δx² + Δy² + Δh²)

∇V_dist = λ_d·(dist - d*)/dist · (Δx, Δy, Δh, 0, 0, 0)    # radial (LOS 방향)

B_d ω-row = (Δy, -Δx, 0, -1, 0, 0)                          # tangential

(B_dᵀ ∇V_dist)_ω = Δy·(λ_d·err·Δx/dist) - Δx·(λ_d·err·Δy/dist) - 1·0
                = (λ_d·err/dist) · (Δy·Δx - Δx·Δy)
                ≡ 0
```

**증명 직관**: ∇V_dist 는 LOS 방향 (radial). B_d 의 ω 행 은 LOS 수직 방향 (tangential). 두 벡터의 내적은 항상 0. *우리 turn (ω) 으로는 dist 못 줄임*.

**Z3 검증**: `tools/basis/verify_h1_omega_zero.py` 가 NRA fragment 로 PROVED.

**함의**:
- V_PN 의 dist 항이 *우리 turn 으로* 신호 보낼 수 없음
- dist-닫기 신호는 *오직* γ̇ 채널 (Δh 경유) 또는 a 채널 (V_target)
- aggressive 매치에서 *양쪽 동일 alt* → γ̇ 채널도 약함 → *dist 못 닫음의 수학적 근거*

### 2.8 τ-blend (softmin, PLAN §2.6.5)

여러 BFM mode 동시 활성 시 *부드러운 blend*:

```
∇V_approx = (Σ τ_i · ∇V_i) / Σ τ_i      # weighted average
u* = optimal_control(∇V_approx)
```

- τ_i ∈ [0, 1]: mode i 의 *현 상황 적합도*. obs 함수 (`tau_functions.py`).
- Σ τ_i ≤ 1 권장 (잔여 = PN baseline)
- T → 0 (temperature → 0): argmax 형태 (분기 quantize)
- T → ∞: uniform (모든 mode 동일 가중)

**우리는 τ-blend (T=1) 사용** — 부드러운 mode 전환.

## §5. 핵심 발견 — 학생에게 가르치는 6개

### 발견 1: H1 Lemma (수학적 증명)

**문제**: 우리 V_dist 가 *왜* dist 못 줄이나?

**증명**:
```
∇V_dist 가 LOS-radial (적 방향 vector)
B_d 의 ω-row 가 LOS-tangential (LOS 수직)
두 벡터 내적 ≡ 0 (Z3 PROVED)
```

**의미**: 우리 turn (ω) 으로는 *수학적으로* dist 못 줄임. 적이 우리 옆 멀리 있으면 turn 만으로 영원히 못 잡음. dist-닫기는 *γ̇ 채널 (alt 변화)* 또는 *a 채널 (sprint)* 으로만.

### 발견 2: aggressive Nash equilibrium

**실측** (3 매치 평균):
- canonical dist 3298 → mean 15,116 ft (5분 동안 발산)
- closure mean -22 kts (평균적으로 멀어짐)
- 35% 시간 closing (>50 kts), 45% 시간 extending (<-50 kts) → 진동

**메커니즘**:
- 우리 max accel + turn-toward → V_p 손실 (turn drag) → 적이 추월
- 적 BT (yaml `Pursue+Accelerate` 무조건) → 적도 V_e=480 (max) 유지
- 양쪽 corner-speed parallel chase → turn rate 동일 → 영원히 평행

**게임이론**:
- 동일 envelope + 동일 정책 클래스 + symmetric IC = **Nash equilibrium 자명**
- 어느 쪽도 혼자 행동 변경 시 *더 불리* → 현 상태 유지가 최선

### 발견 3: v11 sim 검증으로 *BT 결함 아닌 게임 wall* 확정

|---|---|

| orbiting | WIN |

| evading | WIN |

→ **v11 도 offensive 만 못 잡음**. 우리 pursuit_chase_v1 의 aggressive DRAW 와 정확히 같은 패턴.

**결론**: BT 의 결함이 아닌 *adversary "always lead-PN + accel + no break" 의 구조적 Nash*. 어떤 closed-form BT 도 풀이 불가.

### 발견 4: 적의 수직 약점 (v11 source 발견, 그러나 실제로는 미작동)

**v11 의 offensive adversary 소스 (line 269)**:
```python
d_gamma = (elev_to_own - enemy.gamma) / (DT * 4.0)  # 수직 4s lag
d_hdg = ... / (DT * 2)                              # 수평 0.4s
```

→ **수직 응답 시간상수 4초 vs 수평 0.4초 (10× lag)**.

**우리 시도 (ZoomDive)**:
- 우리 climb (γ=15°): 4초 동안 alt gain ≈ 4 × 200 m/s × sin(15°) ≈ 207 m ≈ **680 ft**
- 적도 4초 후 climb 시작 → alt_gap = 680 ft 유지 (커지지 않음)
- 4000 ft 우위 *수학적으로* 불가

**측정**: aggressive max\|dh\| = 2773 ft (≪ 4000) → ZoomDive 의 Z3 (dive) phase 영원히 비활성.

### 발견 5: simple 평형의 fragility

**baseline**: simple 12W/0L 결정적.

**fragility**: 어떤 dispatcher 변경도 *simple 평형 깸* 위험.
- yoyo τ=0.29 (Theorem) 의 6% 감소 → simple WIN 손실 (D-Obs-2b)
- Theorem 의 argmax-quantize → simple 12W → 0W (D1)
- bias_tau_T (0.3) → simple 5W → 0W (C2)

**해석**: simple WIN 의 *manifold* 가 매우 좁음. 단순 추격하는 simple 적에는 *우리 turn 의 정확한 ATA 잡기* 가 필요하고, 그 turn 의 *세부 가중치* 변경이 catastrophic.

### 발견 6: Model B' running cost ≡ 0 in aggressive

PLAN §11.7 의 Model B' = HP 누적 running cost game:
```
J = ∫_0^T (D_them - D_us) dt + g(x_T)
D(x) = 25 · w_ATA · w_dist  HP/s   (x ∈ WEZ 안에서만 nonzero)
```

**aggressive 매치 9000 BT ticks 측정**:
- D_us active: 0/9000 (0.0%)
- D_them active: 0/9000 (0.0%)
- → **J ≡ 0 항상**, cost gradient 도 0

**의미**: Model B' 로 paradigm 변경해도 aggressive 매치에선 *signal 자체* 없음 → 어떤 cost-based optimization 도 무효.

## §6. 학생 학습용 핵심 개념

### 6.1 Nash equilibrium (직관)

**정의**: 두 player 모두 *자기 최선* — 어느 쪽도 혼자 행동 바꿔 더 나아질 수 없는 상태.

**우리 aggressive 매치**:
- 우리 *직진+accel* → 적이 *우리 향해 turn+accel* → 우리 잘 못 잡음
- 우리 *turn-toward-enemy* → V_p 손실 → 적이 추월 → 더 못 잡음
- 우리 *break-turn-away* → 적이 *우리 더 잘 따라옴* → 더 멀어짐
- → **어떤 우리 행동도 *더 나빠짐*** → 현 상태 (parallel chase) 가 우리 *최선*

같은 logic 으로 적도 *어떤 행동도 더 나빠짐* → 적도 현 상태가 최선.

→ **Nash equilibrium = 둘 다 갇힘 = DRAW**.

### 6.2 Symmetric trap (DSBT §6.1 (a))

**정리**: 동일 envelope + 동일 IC + 동일 정책 클래스 → Nash 자명 (game value 0).

**우리 게임**: F-16 (envelope) + abeam IC + closed-form policy class (둘 다 ∇V_i 식 의 변형) → game value 0 (DRAW).

**깨는 path 4가지 (DSBT §7.1)**:
1. **Information asymmetry** — 한쪽이 더 많이 관측 (불가능 — 양쪽 28 obs)
2. **적 비최적 정책 exploit** — 적이 *Nash 안 함* → 약점 찾기 (aggressive 의 *고정 BT* 는 일종의 비최적이지만, 그 약점이 *수직 4s lag* 만 — 실측에서 무효)
3. **초기 perturbation** — IC 가 비대칭 (불가능 — canonical IC 강제)
4. **Belief 정확도 우위** — 적 정책 추정 (R2 위반)

→ 4개 모두 우리 환경에서 *실현 어려움*.

### 6.3 V (value) function 의 의미

**Lyapunov 관점**: V(x) = "현재 상태에서 *이상적 상태까지의 거리*". 우리는 *V 최소화* 정책 선택.

**Hamilton-Jacobi 관점**: V*(x) = "최적 정책 하 *기대 cost*". minimax (us min, them max) 게임.

**우리 V_i 들은 *근사*** — 진짜 game-theoretic V* 가 아닌 *BFM mode 별 heuristic Lyapunov*. 정확도:
- G1 게이트 (FD 검증) ✓ closed-form 자체는 정확
- LUT 검증 (RT-3): 진짜 HJI V* 와 cos≈0 (closed-form ∇V 가 game-theoretic V* 와 *방향* 다름)

→ 우리는 *heuristic Lyapunov* 사용. *진짜* Nash 깨려면 *진짜 V** 필요.

### 6.4 R1~R9 ground rules (왜 중요)

| 규칙 | 왜 |
|---|---|
| **R1**: 수치 fine-tuning 금지 | 임계값 sweep 은 우연 발견. *왜 작동하는지* 모르면 다음 변경 시 회귀 |
| **R2**: 추정기 금지 | 학습된 추정기는 *데이터 의존* — 환경 변화 시 약함. obs 직접 사용이 robust |
| **R3**: G1 항상 통과 | ∇V 의 *수학적 정확성* 보장 (closed-form 의 가치) |
| **R4**: Z3 정당화 | sign/monotone 같은 *구조적* 속성은 SMT 로 *형식 검증* 가능 |
| **R5**: 누적 회귀 검증 (≥5 매치) | n=1,2 는 FP basin 변동 큼. n=5+ 가 statistical signal |
| **R6**: 5가정 점검 | "이론적 불가" 는 *대개 잘못된 가정*. 5가지 (ω 상수, 적 최적, 2D, 닫힌 궤도, 정적 정책) 점검 |
| **R7**: 회귀 hard-gate | "다른 stage 개선되니까 simple 미세 회귀 OK" 함정 회피 |
| **R8**: 1-변경 원자성 | 동시 다중 변경 = 디버깅 불가. revert 명확성 위해 1-by-1 |
| **R9**: snapshot 보존 | 매 stage WIN 시점 backup → revert 즉시 가능 |
