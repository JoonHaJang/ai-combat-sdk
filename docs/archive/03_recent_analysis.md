# 03. 최근 분석 — 자연어로 풀이

> **이 문서의 용도**: 최근 작업(2026-04 ~ 05)에서 무엇을, 왜, 어떻게 했는지를
> **수식·약자 없이** 풀어 설명. 정확한 코드 위치나 측정값은 다른 문서로.

---

## 1. 출발점 — "왜 우리 AI가 어떤 적에는 무승부만 내는가"

작년에 만든 AI(`adaptive_eagle_v11`)는 강한 적 일부에는 잘 통하는데, **표준
시작 조건에서 공격형(offensive) 적에게 무승부**가 자주 나왔습니다. 격추도 못
하고 격추당하지도 않는 상태로 5분이 그냥 흘러감.

**관찰한 패턴**:
- 적도 우리도 양쪽으로 갈라지면서 빙빙 도는 모양
- 둘 다 같은 속도 같은 선회율 → 어느 쪽이 먼저 뒤를 못 잡음
- 사거리 안에 들어오는 순간이 있어도, 그 순간에 거리는 **벌어지고 있어** 데미지 누적 안 됨

이걸 그냥 "튜닝 더 하자"가 아니라 **수학적으로 왜 이런가** 를 따져보기 시작.

---

## 2. 첫 번째 가설 — "묶인 궤도(Bound Orbit)" 설명

천체역학에서 두 별이 서로 끌려서 영원히 같은 거리로 도는 게 "묶인 궤도".
우리 두 비행기도 비슷한 상황 아닌가?

계산해봤더니:
- 두 비행기가 같은 속도(387kts) 같은 최대 선회율(21°/s)로 돌면
- **자연 궤도 반경 = 2 × 속도 / 선회율 ≈ 3500ft**
- 우리 시작 거리 = 3297ft → 거의 자연 궤도

→ "두 비행기가 평면에서 빙빙 돌고 있으면 ATA(내 기수와 적 사이 각도)가 90°에
**고정**(locked)되어 영원히 풀리지 않는다" 라는 잠정 결론.

---

## 3. 그러나 — 사용자가 5단계로 깨준 잘못된 가정

이 "묶인 궤도" 설명은 그럴듯했지만 **틀렸습니다**. 사용자가 단계별로 지적:

**단계 1** — "선회율은 상수인가?"
- 처음 분석에서 선회율 ω를 21°/s로 박아둠
- 실제로는 **속도 의존**: 350kts에서 최대 21°/s, 387kts에서는 19.15°/s
- 속도 바꾸면 ω 바뀜 → 궤도 락이 깨짐

**단계 2** — "조종사가 매 순간 판단할 수 있다"
- 선회 시작할 때 r과 ω 정해놓고 그대로 가는 게 아님
- 관측값 보면서 매 틱 속도/피치/롤을 새로 정함 → **적응형 선회**

**단계 3** — "이건 3D 문제"
- "묶인 궤도" 분석은 2D 평면. 실제 도그파이트는 위·아래(γ 자유도)도 있음
- 평면 락은 수직 break 하나로 깨짐

**단계 4** — "적은 black-box"
- 게임 이론에서 "둘 다 최적이면 무승부"는 둘 다 **완벽한 적**일 때
- 실제 적은 고정된 휴리스틱(우리는 알 수 없지만 결정론적) → 약점 exploit 가능
- 따라서 무승부 정리 적용 안 됨

**단계 5** — "궤도가 원/타원만 있는 게 아니다"
- 케플러 닫힌 궤도(원·타원)에만 가둬서 분석 → 폭이 좁음
- 실제 비행 궤적은 8자, 나선, 가위질, 갑작스런 break 등 다 가능
- 닫힌 궤도 분석이 무의미

→ **결론**: "묶인 궤도라서 어쩔 수 없음" 은 거짓. 진짜 원인은
**우리 BT가 적의 약점을 활용하지 못해서**.

---

## 4. 두 번째 시도 — 수학 정리를 BT 분기로 박기 (폐기됨)

BFM(Basic Fighter Maneuvers) 교과서들엔 1930년대부터 축적된 **수학 정리**가
있습니다. 예: Boyd Energy-Maneuverability, Shaw 1-circle/2-circle, Pontryagin
yo-yo 최적 제어.

이 정리들을 코드에 박아 넣었습니다:

```python
# 첫 시도 (폐기)
if HCA > 120 and 우리_속도 > 360 and ATA > 30 and 거리 > 2500:
    return "EnergyTrapForceCorner"  # 코너 속도로 brake
```

**결과**: 78% → 89% WIN (좋아짐)

**그런데 사용자가 또 지적**:

> "이건 우리 방식의 fine-tuning이지, 적이 변하면 깨진다.
> 수학 공식이 적의 동적 변화에 따라 적응적으로 동작해야 함"

맞는 말. 120°, 360, 30°, 2500ft 같은 임계값은 우리가 정한 거고,
적이 다르게 행동하면 무용지물.

**폐기**.

---

## 5. 세 번째 시도 — τ 연속 가중 (현재 방식)

핵심 아이디어:

> **"이 BFM 정리를 켤까/끌까(0/1)" 가 아니라
>  "지금 얼마나 강하게 쓸까(0~1 연속)"** 를 매 틱 obs에서 직접 계산.

τ(타우)는 그 0~1 점수입니다. 각 BFM 정리마다 τ 함수가 하나 있고, 모두
**관측값(obs)의 직접 함수**입니다 — 별도 추정기 없음.

### 5.1 τ_corner (정리 5+6, Boyd + Shaw)

> "지금 코너 속도(350kts)로 감속해야 할까?"

```
τ_corner 가 높아지는 조건:
  - HCA(두 헤딩 사이 각) > 120° (양쪽이 서로 마주 보며 도는 중 = 2-circle)
  - 내 속도 > 355kts (코너 위에 있음)
  - 둘 중 하나가 능동적으로 돌고 있음 (turn rate 큼)
```

세 조건이 다 만족이면 τ_corner ≈ 1.0 → "전력 brake"
하나만 어긋나면 τ_corner 떨어짐 → "감속 약하게"

### 5.2 τ_yoyo (정리 8, Pontryagin)

> "지금 위로 올라갔다 다이브해서 적 6시로 들어가야 할까?"

```
τ_yoyo 가 높아지는 조건:
  - closure(거리 변화율)가 크거나, 반대로 아주 작음 (orbit 락 상태)
  - HCA 높음 (상대방향)
  - ATA 30~110° 범위
```

높으면 위로 climb → 정점 → 뒤집어서 dive → 적 6시 진입.

### 5.3 τ_ldt (정리 7, Shaw Lag Displacement)

> "지금 적 옆으로 우회한 다음 진입해야 할까?"

```
τ_ldt 가 높아지는 조건:
  - ATA 50~80° (중간대)
  - 거리 충분 (3000ft 이상)
  - LOS(시선) 회전이 빠름 — 곧 따라가기 어려워짐
```

### 5.4 결과를 어떻게 합치나 — 가중 합성

```
d_speed (속도 명령)
  = (1 - τ_corner) × 기본_PN_가속 + τ_corner × 코너_brake

d_gamma (피치 명령)
  = (1 - τ_yoyo)   × 기본_PN_피치 + τ_yoyo × yoyo_climb_or_dive

d_hdg (방향 명령)
  = w_pn × 기본_PN + w_dive × 적예측6시조준 + w_lag × 90°옆으로
```

τ가 부드럽게 변하면 명령도 부드럽게 변하고, 적이 변하면 obs가 변하고 τ가
변하고 명령이 따라감 → **자동 적응**.

## 6. 추정기를 안 쓴 이유

처음엔 "적의 응답 시간 같은 걸 추정해서 τ에 넣자"고 생각했는데
사용자가 또 지적:

> "그냥 관측값을 써버려. 직접"
> "상태 추론기보다는, 관측값 기반으로 수학식이 적응형으로 동작해야 함"

이유:
- **추정기는 추정 오차를 도입함** — 실제 측정보다 부정확
- **추정기는 모델 가정에 의존** — 가정이 깨지면 무용지물
- 시간차분 (예: alt_gap 변화율) 은 **이미 obs로 직접 산출 가능**

그래서 모든 τ 함수의 입력은 **28개 obs와 그 시간차분만**. 추정기 0개.

## 7. 결과

검증 시뮬에서 측정 (2026-05-01):

```
WIN  =  50 / 55  (91%)
LOSS =   0 / 55   (0%)
DRAW =   5 / 55   (9%)
```

**중요**: 표준 시작 조건(canonical = ATA=90°, 3297ft, 387kts, 15000ft) ×
5개 적 정책(passive/orbiting/defensive/offensive/evading) = **5/5 WIN**.

남은 5 DRAW는 모두 비현실 / 물리 한계 케이스:
- 시작 거리가 비정상적인 2건 (실 매치는 항상 3297ft)
- 적이 시작부터 MAX_SPD 420kts 인 3건 (동등 성능 가정 위반)

## 8. 한 발짝 물러서서 본 핵심 교훈

얼마인가" 라는 질문 자체가 함정. 관측값에 이미 그 결과가 찍혀 있다.

**교훈 3** — 검증 시뮬에서 91%여도 JSBSim 본 매치에서 보장 안 됨.

**교훈 4** — "수학 이론적으로 못 이긴다" 라는 결론은 가정 5개를 점검해야 함:
선회율 상수, 적 최적성, 2D 평면, 닫힌 궤도, 정적 정책. 하나만 깨도 결론 뒤집힘.
