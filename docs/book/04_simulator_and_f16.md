# 4장. 시뮬레이터와 F-16 6자유도 모델

## 학습 목표
이 장을 마치면 다음을 할 수 있다.
- 왜 실제 비행기 대신 시뮬레이터 위에서 AIPILOT을 만드는지 설명한다.
- 6자유도(6-DOF) 강체 비행이 무엇인지, 어떤 상태로 기술되는지 안다.
- JSBSim이 무엇이고 비행기를 어떻게 표현하는지 설명한다.
- 우리가 쓰는 F-16 모델의 출처가 왜 믿을 만한지 안다.
- 우리 상태 벡터 10개와 입력 4개가 무엇이며 단위가 어떻게 되는지 적는다.
- 평형 비행(trim)을 구한다는 것이 무엇이고 왜 필요한지 설명한다.

이 장은 2부의 첫 장이다. 1부에서 우리가 풀 문제(1대1 dogfight)를 정의했다면, 이제 그 문제를
무엇 위에서 푸는지, 곧 비행기와 시뮬레이터라는 토대를 세운다. 이후 3부의 제어는 이 토대 위에서
비행기를 목표대로 날리는 일이다.

---

## 4.1 왜 시뮬레이터 위에서 만드나

자율 조종사를 실제 F-16에 바로 태울 수는 없다. 우리는 비행기를 수학적으로 흉내 내는 시뮬레이터
위에서 만든다. 시뮬레이터를 쓰는 이유는 셋이다.

첫째, 안전과 비용이다. 추락해도 잃는 것이 없으니 수천 판을 돌릴 수 있다. 둘째, 재현성이다. 같은
초기 조건에서 같은 입력을 넣으면 언제나 같은 결과가 나와, 실험을 반복하고 비교할 수 있다. 셋째,
인용 가능성이다. 우리가 쓰는 시뮬레이터는 공개되어 있고 공력 모델의 출처가 학술 보고서에 있어,
결과를 논문처럼 근거와 함께 제시할 수 있다.

이 책의 모든 비행은 오픈소스 시뮬레이터 JSBSim의 F-16 모델 위에서 일어난다.

## 4.2 6자유도란 무엇인가

비행기를 하나의 강체로 보면, 공간에서의 움직임은 여섯 개의 자유도로 완전히 기술된다. 위치 세 개와
자세 세 개다. 위치는 앞뒤, 좌우, 상하의 이동이고, 자세는 세 축에 대한 회전이다. 회전 세 축에는
이름이 있다.

```
                기수(앞)
                  ↑ x축 (전방)
                  |
   좌 ──────────[기체]────────── 우  y축 (우현)
                  |
                  ↓ z축 (하방, 지면 쪽)

  롤(roll,  phi) : x축(전후축) 둘레 회전 — 좌우로 기울임(뱅크)
  피치(pitch,theta): y축(좌우축) 둘레 회전 — 기수 들고 내림
  요(yaw,  psi) : z축(상하축) 둘레 회전 — 기수 좌우로 돌림
```

이 좌표계를 기체 좌표계(body frame)라 한다. x는 기수 방향(전방), y는 오른쪽 날개 방향(우현),
z는 아래(지면 쪽)다. 비행역학에서는 z가 위가 아니라 아래임에 주의한다.

여섯 자유도의 운동은 뉴턴-오일러 방정식으로 적분된다. 힘은 속도를, 모멘트(회전력)는 각속도를
바꾼다. 힘과 모멘트는 공력(날개와 동체가 공기에서 받는 힘), 추력(엔진), 중력에서 온다. 시뮬레이터가
하는 일은 매 순간 이 힘과 모멘트를 계산해 방정식을 한 걸음 적분하는 것이다.

제어 설계에서는 이 6자유도를 보통 12개 상태로 적는다. 위치 3, 자세 3(phi, theta, psi), 속도 3,
각속도 3(p, q, r)이다. p, q, r은 각각 롤, 피치, 요의 각속도다. 우리는 이 가운데 제어와 유도에 필요한
부분집합을 쓴다(4.5).

## 4.3 JSBSim — 오픈소스 비행역학 엔진

JSBSim은 공개 비행역학 모델 라이브러리다(FDM, Flight Dynamics Model). C++로 작성되었고 파이썬에서
바로 쓸 수 있으며(pip jsbsim), LGPL 라이선스로 배포된다. 비행기 한 대는 XML 파일들로 기술된다.
공력 계수표, 엔진, 질량과 관성, 조종면, 그리고 비행제어 시스템(FLCS)이 모두 XML 안에 있다.

JSBSim의 동작은 속성 트리(property tree)로 드러난다. 모든 상태와 입력이 문자열 경로를 가진 속성으로
노출된다. 예를 들어 진대기속도는 velocities/vt-fps, 받음각은 aero/alpha-rad, 고도는
position/h-sl-ft 이다. 조종 입력도 속성으로 넣는다. fcs/elevator-cmd-norm 에 값을 쓰면 엘리베이터
명령이 된다. 우리 코드는 이 속성 트리를 통해 상태를 읽고 입력을 쓴다.

JSBSim을 택한 또 하나의 이유는 인용이다. JSBSim은 공력 모델링에 매우 정확하다고 널리 인정되는
오픈소스 소프트웨어이므로, "우리 비행은 JSBSim에서 돌았다"는 문장만으로 방법의 신뢰성을 근거와
함께 말할 수 있다.

## 4.4 F-16 모델의 출처

우리가 쓰는 F-16 모델은 임의로 만든 것이 아니라 공개된 학술 자료에 뿌리를 둔다.

공력의 핵심 출처는 NASA 기술보고서 TP-1538(Nguyen 외, 1979)이다. 이 보고서는 종방향 정안정성을
완화한 전투기의 실속 및 실속 후 특성에 관한 시뮬레이터 연구로, 넓은 받음각 범위의 F-16급 공력
데이터를 담는다. 이 데이터는 표준 교재인 Stevens와 Lewis의 Aircraft Control and Simulation에서
F-16 비선형 모델로 정리되었고, 이후 여러 공개 구현으로 이어졌다. NASA NTRS에는 Morelli의 전역
비선형 다항식 F-16 모델도 공개되어 있어, 같은 공력을 다항식 형태로도 쓸 수 있다(7부 INDI 검증에서
이 다항식 모델을 별도 plant로 사용한다).

우리 저장소는 JSBSim용 F-16 데이터를 함께 담는다(new_match_engine/jsbsim_data). 이 데이터에는
F-16의 native FLCS, 곧 기체에 내장된 비행제어 안정성 증강 장치가 포함된다. 이는 4.5에서 보듯 우리
입력 규약과 직접 관련된다. 이 번들 데이터는 LGPL 라이선스이며 출처를 함께 표기한다.

요약하면, 공력은 NASA TP-1538에, 모델 정리는 Stevens와 Lewis에, 실행은 JSBSim에 근거한다. 모두
공개되어 있어 재현과 인용이 가능하다.

## 4.5 우리가 쓰는 상태와 입력

우리는 12개 상태 중 제어와 유도에 필요한 10개를 상태 벡터로 쓴다. 종방향(앞뒤·상하 운동), 횡방향
(좌우·회전 운동), 항법(위치)으로 묶인다.

```
x = [ V,  alpha, theta, q,    |  beta, phi, p, r,    |  h,  psi ]
      └──── 종방향 ────┘         └──── 횡방향 ────┘       └ 항법 ┘

  V     진대기속도        (fps)        beta  옆미끄럼각      (rad)
  alpha 받음각            (rad)        phi   뱅크각          (rad)
  theta 피치 자세각       (rad)        p     롤 각속도       (rad/s)
  q     피치 각속도       (rad/s)      r     요 각속도       (rad/s)
                                       h     고도            (ft)
                                       psi   방위            (rad)
```

코드에서 이 대응은 plant.py의 STATE_PROPS와 STATE_ORDER에 정의되어 있다. 각 상태는 JSBSim 속성
하나에 매핑된다(예: V는 velocities/vt-fps).

입력은 네 개다.

```
u = [ throttle, elevator, aileron, rudder ]
      0 .. 1     -1 .. 1   -1 .. 1   -1 .. 1
```

여기서 중요한 점이 하나 있다. 우리 입력은 조종면 각도가 아니라 명령 정규값(command normalized)이다.
JSBSim의 fcs/elevator-cmd-norm 같은 속성에 넣으면, F-16의 native FLCS가 그 명령을 받아 안정성
증강을 거친 뒤 실제 조종면을 움직인다. 다시 말해 우리는 조종간에 해당하는 명령을 주고, 기체 내장
FLCS가 그 아래에서 실제 타면 편향을 만든다. 이 계층 덕분에 우리 제어기는 FLCS가 이미 안정화한
기체를 다룬다.

단위 규약은 표기법 장과 일치한다. 외부 인터페이스(관측·유도)는 도, 피트, 노트를 쓰고, 제어 내부와
plant는 라디안, 피트퍼초를 쓴다. 경계에서만 변환한다.

## 4.6 plant.py — 시뮬레이터 래퍼

plant.py는 JSBSim을 우리 코드가 쓰기 쉬운 객체로 감싼다. 핵심 메서드는 다음과 같다.

```
F16Plant.set_ic(alt_ft, vc_kts, gamma_deg, psi_deg)  # 초기 조건 설정 + run_ic + 엔진 시동
          .trim(mode=1)                              # 평형 비행 맞추기
          .step(n=1)                                 # n 스텝 적분
          .get_state()                               # 상태 벡터 x 읽기
          .set_input(u)                              # 입력 u 쓰기
```

데이터 흐름은 단순하다. 초기 조건을 정하고, 평형을 맞추고, 매 tick 입력을 쓰고 한 걸음 적분하고
상태를 읽는다.

```
set_ic  ─►  trim  ─►  [ 반복 ] set_input(u) ─► step() ─► get_state()
```

여기서 반드시 짚어야 할 함정이 있다. 엔진 시동이다. 초기 조건을 설정한 직후 엔진이 시동되어 있지
않으면 추력이 거의 0이 되어, 비행기가 동력 없이 활공한다. 이 상태에서는 속도를 올리는 어떤 제어도
듣지 않는다. plant.py는 set_ic 안에서 start_engines를 호출해 모든 엔진을 running 상태로 만든다.
검증에 따르면 시동 전에는 추력이 음수(약 -1383 lbf, 곧 램항력만)이고, 시동 후에는 약 +17116 lbf가
된다. 이 한 줄이 빠지면 모든 속도 제어가 무력화되므로, 시뮬레이터를 직접 다룰 때 가장 먼저 확인할
부분이다.

## 4.7 평형 비행(trim)을 구한다는 것

trim은 비행기를 정상 비행 상태, 곧 가속도가 0인 균형 상태로 맞추는 일이다. 정해진 고도와 속도에서
힘과 모멘트가 서로 상쇄되도록 받음각과 조종면, 추력을 찾는다. 평형에서는 비행기가 스스로 그 상태를
유지하므로, 그 점을 기준으로 작은 변화를 따질 수 있다.

trim이 왜 중요한가. 다음 장(5장)에서 우리는 비선형 동역학을 운영점 근처에서 직선으로 근사한다.
그 운영점이 바로 trim이다. trim이 정확해야 선형화가 정확하고, 그래야 그 위에 세운 LQR 제어기가
제대로 작동한다. 즉 trim은 제어 설계의 출발점이다.

코드에서 trim은 JSBSim의 do_simple_trim을 호출해 공중 평형을 맞춘다(plant.py의 trim 메서드).
초기 조건을 고도 15000피트, 속도 350노트로 두고 trim을 부르면, 받음각 약 3.4도, 엘리베이터 약
-1.65도, 스로틀 약 0.14 부근의 평형이 나온다. 이 값들이 5장의 선형화와 6장의 LQR이 기준으로 삼는
운영점이다.

## 4.8 시간 적분과 tick

JSBSim은 내부에서 고정 주기로 비행 방정식을 적분한다. 우리 설정에서 물리 적분은 초당 120회다.
한 번의 step 호출이 한 번의 적분이며, plant.dt가 그 주기(약 1/120초)를 알려준다. 제어는 그보다
느린 초당 20회, 의사결정은 초당 10회로 돈다. 즉 제어 한 tick마다 물리는 여러 번 적분되고, 의사결정
한 tick마다 제어가 여러 번 돈다. 이 다중 주기 구조는 13장 시스템 아키텍처에서 다시 다룬다.

```
물리 120Hz : | | | | | | | | | | | | ...   (step 한 번 = 적분 한 번)
제어  20Hz : |     |     |     |     ...     (조종면 갱신)
결정  10Hz : |           |           ...     (전술 선택)
```

## 4.9 상태 캡처와 복원

오프라인 정책 도출(12장)에서는 한 상태에서 여러 전술을 짧게 시뮬레이션해 비교한다. 이를 위해
plant.py는 현재 비행 상태를 스냅샷으로 저장하고 되돌리는 기능을 제공한다(capture_state,
restore_state). JSBSim은 직접 직렬화를 제공하지 않으므로, 위치·자세·기체속도·각속도를 초기 조건
속성으로 다시 넣어 복원한다. FLCS 내부 적분과 조종면 위치는 재설정되어 1초 미만의 짧은 과도가
생기지만, 전술 선택용 짧은 시뮬레이션에는 무해하다.
