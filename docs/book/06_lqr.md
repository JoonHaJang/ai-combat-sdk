## 0. 한눈에 — 결론부터

1. **문제는 비선형**이다 (항공기 6-자유도 동역학 `ẋ = f(x,u)`). 그러나 우리는 *교전 내내 평형
   부근에서 기동*하므로, **평형점(trim) 주변에서 국소 선형화**하면 그 근방은 선형 시스템
   `δẋ = A δx + B δu`로 정확히 근사된다.
2. 이 국소 선형계에 대해 **LQR(Linear-Quadratic Regulator, 선형-2차 최적조절기)**: 2차 비용을
   최소화하는 *최적* 상태피드백 `u = u₀ − K(x − x*)`를 **Riccati 방정식**으로 닫힌형으로 구한다.
3. **안정성은 정리로 보장**된다: `(A,B)` 가제어(stabilizable)·`(A,√Q)` 가관측(detectable)이면
   닫힘루프 `A−BK`의 모든 고유값이 좌반평면(LHP) → **점근 안정**. 코드가 9개 운영점 전부에서
   이를 수치로 검증한다(`stable=True`).
4. **하나의 평형점은 좁다.** 비행 포락선 전체는 **게인 스케줄링**(운영점 격자 위 LQR을 미리 풀고
   런타임에 보간)으로 덮는다 — 비선형 시스템을 *국소 선형계의 모음*으로 다루는 표준 기법.
5. **고수준(어떤 기동)과 저수준(조종면)을 cascade로 분리**: 외측 루프(PI/P)가 setpoint(ψ*,h*,V*)를
   *내부 상태 기준 x\**로 번역하고, 내측 LQR이 `x → x*`를 추종한다.

<a id="s1"></a>
## 1. 풀려는 문제 (목적과 설계)

**목적.** 상위 의사결정층이 준 *목표값(setpoint)* — 목표 heading ψ*, 고도 h*, 속도 V* — 을 받아,
F-16의 네 조종 입력 `u = [throttle, elevator, aileron, rudder]`를 매 제어주기(20 Hz)마다 산출해
**기체를 그 목표 자세·궤적으로 안정되게 몰아가는** 저수준 제어기.

**왜 어려운가.** 항공기 동역학은 **비선형**이다(공력·관성 결합, 삼각함수, 받음각 의존 양력 등).
비선형 최적제어를 매 0.1초 풀 수는 없다 — 실시간이 불가능하고, 보장도 어렵다.

**설계 결정 — 두 가지 분리.**
- **(공간 분리) 국소 선형화 + 게인 스케줄링**: 비행 상태는 *평형 부근*에 머무므로, 평형점마다
  선형 모델을 만들어 *최적*으로 풀고(LQR), 포락선은 그 점들의 보간으로 덮는다.
- **(역할 분리) cascade**: "어디로 갈지(ψ*,h*,V*)"는 외측 루프가, "그 자세를 어떻게 안정 유지할지"는
  내측 LQR이. 빠른 자세 동역학과 느린 항법 동역학을 시간척도로 분리(singular perturbation 관점).

**왜 LQR인가 (방법론 선택 근거).** *LQR*은 선형 시스템 + 2차(quadratic) 비용에 대해 **최적 피드백을
닫힌형(Riccati)으로** 주고, **안정성·게인여유를 정리로 보장**하며(고전 LQR은 60° 위상여유·무한대
게인여유 보장), 게인 `K`가 *해석 가능한 행렬*이라 인용·검증이 쉽다. RNN 같은 블랙박스 저수준
제어를 **투명·증명가능** 제어로 대체하려는 프로젝트 목표에 정확히 부합한다.
> 출처: Stevens, Lewis & Johnson, *Aircraft Control and Simulation*, 3rd ed., [§5](#s5)–6.

## 2. 플랜트(plant) — F-16 비선형 6-자유도 동역학

제어 대상(plant)은 JSBSim의 F-16 모델(native FLCS + 기체)이다. 동역학은 비선형 상태방정식

```
ẋ = f(x, u)          (연속시간 비선형 동역학)
```

으로 쓴다. 우리가 제어에 쓰는 **상태 x ∈ ℝ¹⁰** (`plant.py: STATE_ORDER`):

| i | 기호 | 의미 | 단위 | 묶음 |
|---|---|---|---|---|
| 0 | V | 진대기속도(TAS) | ft/s | 종(lon) |
| 1 | α | 받음각(angle of attack) | rad | 종 |
| 2 | θ | 피치각(pitch) | rad | 종 |
| 3 | q | 피치율 | rad/s | 종 |
| 4 | β | 옆미끄럼각(sideslip) | rad | 횡(lat) |
| 5 | φ | 롤각(bank) | rad | 횡 |
| 6 | p | 롤율 | rad/s | 횡 |
| 7 | r | 요율 | rad/s | 횡 |
| 8 | h | 고도(MSL) | ft | 항법 |
| 9 | ψ | 방위각(heading) | rad | 항법 |

**입력 u ∈ ℝ⁴** (`INPUT_ORDER`): `throttle∈[0,1]`, `elevator·aileron·rudder ∈[−1,1]` (정규화).

이 10·4 분할은 의도적이다 — **종(longitudinal) {V,α,θ,q}** 과 **횡-방향(lateral-directional)
{β,φ,p,r}** 은 1차적으로 *분리된* 동역학이고([§7](#s7)), {h,ψ} 는 자세의 적분으로 따라오는 *항법* 상태라
내측 LQR이 직접 좇지 않는다([§5](#s5), [§9](#s9)).

## 3. 비선형 문제를 선형으로 — 정당성과 증명

가장 많이 받은 질문이자 이 문서의 핵심이다. **"비선형 시스템을 선형 제어기로 다뤄도 되는가, 그게
증명되는가?"** 답은 *그렇다 — 단, "국소적으로"라는 단서와 함께*. 직관부터 쌓고, 그다음 두 정리로
엄밀히 증명한다.

> **먼저 직관.** 비행기는 매 순간 "거의 정상비행(steady flight)" 부근에 있다 — 정상 수평비행, 정상
> 선회, 정상 상승. 이 *정상 상태(평형)*에서 살짝 벗어난 이탈만 다루면, 그 이탈의 동역학은 *놀랍도록
> 정확히 선형*이다. 그래서 "비선형을 통째로 푸는" 대신 "평형 부근의 선형 동역학을 푼다". 그리고 그게
> 왜 정당한지는 두 고전 정리(Hartman–Grobman, Lyapunov 간접법)가 보장한다.

<a id="s3-1"></a>
### 3.1 평형점(trim)의 정확한 정의
**평형점(equilibrium)** `(x₀, u₀)`는 *동역학이 멈춘 상태가 아니라, 가속도가 0인 정상 상태*다:
```
f(x₀, u₀) = 0        (상태 미분이 0 — 속도·자세율·각가속도가 정상값으로 유지)
```
항공에서 이를 **trim**이라 한다. 예: alt=15000 ft, V=350 kts의 정상 수평비행을 유지하는
(받음각 α₀, 조종면 δ₀, 추력 T₀). `plant.trim()`이 JSBSim `do_simple_trim`으로 이 대수해를 푼다.
*포물선의 꼭짓점*처럼, 평형점은 동역학을 펼칠 "기준 원점"이다.

<a id="s3-2"></a>
### 3.2 국소 선형화 — 테일러 정리와 **나머지항**(오차가 얼마나 작은가)
`f`가 평형 부근에서 충분히 매끄러우면(C², F-16 공력은 그렇다), **테일러 정리**로 *정확한 등식*을
쓸 수 있다 — 근사가 아니라 등식 + 명시적 나머지:
```
f(x,u) = f(x₀,u₀) + A·δx + B·δu + r(δx,δu)
         └─ =0 ─┘   └─ 1차 선형 ─┘   └ 나머지 ┘
   A = ∂f/∂x|₀ (10×10),  B = ∂f/∂u|₀ (10×4),   δx=x−x₀, δu=u−u₀
```
**핵심은 나머지항 `r`의 크기**다. 테일러 정리는
```
‖ r(δx,δu) ‖ ≤ C · ( ‖δx‖² + ‖δu‖² )        (2차 — 이탈의 *제곱*에 비례)
```
임을 보장한다(`C`는 2계 도함수 상한). 즉 이탈이 절반이면 오차는 **1/4**로 준다. 작은 이탈에서
선형항이 *지배*하고 나머지는 *2차로 무시 가능*하다. trim에서 `f(x₀,u₀)=0`이므로 결국:
```
δẋ = A δx + B δu + r,   ‖r‖=O(‖δ‖²)          (★ 국소 상태방정식 + 오차한계)
```
→ **"비선형 f를 푼 게 아니라, 평형 부근에서 f가 *증명가능하게* 선형에 가깝다는 사실을 쓴다."**

<a id="s3-3"></a>
### 3.3 ★ 증명 ① — 정성적 거동 보존 (Hartman–Grobman 정리)
선형 모델이 *질적으로* 옳은가? 즉 비선형 궤적의 모양(수렴/발산/회전)이 선형과 같은가? 이를 보장하는
고전 정리:
> **정리 (Hartman–Grobman).** 평형점 `x₀`가 *쌍곡(hyperbolic)* — 야코비안 `A`의 모든 고유값 실수부가
> 0이 아님 — 이면, `x₀`의 어떤 근방에서 **비선형 흐름은 선형 흐름과 위상동형(topologically
> conjugate)** 이다. 즉 비선형 궤적은 선형 궤적을 *연속 변형*한 것이라, 수렴·발산·소용돌이 같은
> *정성적 거동이 완전히 일치*한다.

→ F-16 trim의 단주기·dutch-roll 등 모드는 모두 쌍곡(Re≠0, [§4.3](#s4-3)에서 확인)이므로, **선형 모델이
평형 부근 거동을 충실히 대표함이 정리로 보장**된다.

<a id="s3-4"></a>
### 3.4 ★ 증명 ② — 안정성 전이 (Lyapunov 간접법): *"선형이 안정이면 비선형도 국소 안정"*
가장 결정적인 정리. 우리가 [§5](#s5)–6에서 *선형* 닫힘루프를 안정(`A_cl=A−BK` Hurwitz)으로 설계하면,
그것이 **원래 비선형 닫힘루프의 안정으로 옮겨간다**는 보장:
> **정리 (Lyapunov 간접법, first/indirect method).** 비선형계 `ẋ=F(x)`의 평형 `x₀`에서 야코비안
> `J=∂F/∂x|₀`의 *모든 고유값 실수부<0*(Hurwitz)이면, `x₀`는 비선형계의 **국소 점근 안정(locally
> asymptotically stable)** 평형이다. (반대로 한 고유값이라도 실수부>0이면 불안정.)

**증명 스케치 (왜 성립하나).** `J`가 Hurwitz이므로 임의 `Q≻0`에 대해 Lyapunov 방정식
`JᵀP+PJ=−Q`는 유일 해 `P≻0`를 가진다. `V(δx)=δxᵀPδx`를 비선형 닫힘루프를 따라 미분하면
(`F(x)=Jδx+r(δx)`, `‖r‖=O(‖δx‖²)`):
```
V̇ = δxᵀ(JᵀP+PJ)δx + 2 δxᵀP r = −δxᵀQδx + O(‖δx‖³)
```
첫 항(2차 음정)이 둘째 항(3차)을 **작은 근방에서 압도**하므로, 어떤 반경 ρ 안에서 `V̇<0`. Lyapunov
정리에 의해 `δx→0`. ∎
→ **이것이 "비선형을 선형으로 풀었다"의 진짜 증명이다**: 우리는 비선형을 전역으로 푸는 게 아니라,
*선형 설계로 얻은 Hurwitz 보장을 Lyapunov 간접법으로 비선형 국소 안정으로 들어올린다.* [§6](#s6)의 선형
안정성 증명이 이 정리를 통해 **비선형 항공기의 실제 안정성**이 된다.

<a id="s3-5"></a>
### 3.5 유효 영역과 게인 스케줄링 — 국소 증명을 포락선으로 *타일링*
[§3.2](#s3-2)–3.4는 **한 평형점의 근방(끌림영역, region of attraction)** 에서만 성립한다. 근방 밖(다른 고도·
속도, 큰 받음각)에서는 `A,B`가 달라지고 나머지항 `r`이 커져 보장이 약해진다. 해결:
- **여러 평형점**(고도×속도 격자)에서 각각 [§3.2](#s3-2)–3.4를 *따로* 증명·설계 → 각 점마다 "국소 안정
  보장 타일"을 얻는다.
- 런타임에 현재 (h,V)에 맞는 게인을 **매끄럽게 보간**([§8](#s8))해 타일들을 이어붙인다.
- 이것이 **게인 스케줄링(gain scheduling)** = 준-LPV(quasi-Linear-Parameter-Varying): *전역 비선형
  제어를 "국소적으로 증명된 선형 제어들의 매끄러운 모음"으로 구성*하는 항공제어 표준 방법론.
- ★ 단서(정직): 게인 스케줄의 *전역* 안정성은 스케줄 변수(h,V)가 *충분히 느리게* 변할 때만 보장된다
  (slowly-varying 가정). 자세 동역학(빠름)보다 항법(느림)이 느리다는 시간척도 분리([§1](#s1))가 이 가정을
  떠받친다. 급격한 포락선 횡단의 엄밀 보장은 한계([§11](#s11) L4).

> **[§3](#s3) 한 줄**: *비선형을 통째로 풀지 않는다. (i) 평형 부근에서 테일러로 선형화하고(오차는 2차로
> 작음), (ii) Hartman–Grobman으로 거동이 보존됨을, (iii) Lyapunov 간접법으로 "선형 안정 ⇒ 비선형
> 국소 안정"을 증명하며, (iv) 게인 스케줄로 포락선을 국소 증명 타일들로 덮는다.*

<a id="s4"></a>
## 4. 선형화 구현 — A, B를 어떻게 뽑나 (유한차분)

`f`의 해석적 야코비안은 JSBSim 내부(공력표·FLCS)라 닫힌형이 없다. 그래서 **수치 미분(유한차분
중앙차분)** 으로 야코비안을 추정한다 (`linearize.py`).

<a id="s4-1"></a>
### 4.1 trim — 평형점 잡기
`plant.trim()`은 JSBSim의 `do_simple_trim`(in-air trim, mode 1)을 호출 — 주어진 (고도, 속도)에서
가속도가 0이 되도록 받음각·조종면·추력을 푸는 *대수 방정식 해*. 결과가 `(x₀, u₀)`.

<a id="s4-2"></a>
### 4.2 중앙차분 야코비안
미분의 정의를 수치로:

```
A[:,j] = ( f(x₀ + δ·eⱼ, u₀) − f(x₀ − δ·eⱼ, u₀) ) / (2δ)     (상태 j 섭동)
B[:,j] = ( f(x₀, u₀ + δ·eⱼ) − f(x₀, u₀ − δ·eⱼ) ) / (2δ)     (입력 j 섭동)
```

`eⱼ`=단위벡터, `δ`=섭동크기(상태별 물리적 크기로 설정: V는 1 fps, 각은 0.5°, …). **중앙차분**(±δ
양쪽)은 1차 오차를 상쇄해 `O(δ²)` 정확도.

`f(x,u)` 자체의 평가는 *"x를 JSBSim 초기조건(IC)으로 주입 → 입력 u 고정 → n_steps tick → (x_next−x)/(n·dt)"*.
- ★ **n_steps=10 (≈83 ms) 인 이유**: F-16 native FLCS에 *rate-limited 액추에이터*가 있어 1 tick에는
  표면이 거의 안 움직이고 FCS 과도만 잡혀 **B 행렬 부호가 뒤집히는 버그**가 났다. 액추에이터 과도를
  지난 뒤의 *공력 응답*을 포착하려 10 tick 적분한다. (Stevens & Lewis [§5](#s5)의 수치 선형화 주의와 동일.)
- ψ(방위)는 ±π 경계에서 wrap 보정.

<a id="s4-3"></a>
### 4.3 검증 — 고전 비행모드와 대조
추정 `A`의 종 부블록 {V,α,θ,q} 고유값이 F-16 고전 **단주기(short-period)·장주기(phugoid)** 모드와,
횡 부블록 {β,φ,p,r}이 **dutch-roll·roll·spiral** 모드와 일치하는지 본다(`linearize.py: _modes`).
물리적으로 타당한 고유값이 나오면 선형화가 신뢰된다.

<a id="s5"></a>
## 5. LQR — 최적 상태피드백 유도

<a id="s5-1"></a>
### 5.1 무엇을 최소화하나 (방법론 정의)
**LQR**은 *선형* 동역학 + *2차(quadratic)* 비용에 대한 **최적제어**다. 무한구간 비용 범함수:

```
J = ∫₀^∞ ( δxᵀ Q δx  +  δuᵀ R δu ) dt           (Q ≥ 0, R > 0, 대칭)
```

- `δxᵀ Q δx`: 상태 오차의 벌점(목표에서 벗어난 정도). `Q` 대각 = 상태별 가중치.
- `δuᵀ R δu`: 입력 사용의 벌점(조종면을 얼마나 쓰나). `R` 대각 = 입력별 비용.
- 둘의 **trade-off**: Q 크면 빠르고 공격적(입력 큼), R 크면 부드럽고 절약적(느림).

<a id="s5-2"></a>
### 5.2 최적해 — 닫힌형 (Riccati)
최적제어 이론(Hamilton-Jacobi-Bellman → 선형-2차의 경우)이 보장하는 결과:
**최적 입력은 선형 상태피드백** `δu* = −K δx`, 게인은

```
K = R⁻¹ Bᵀ P
```

여기서 `P = Pᵀ ≥ 0`는 **연속시간 대수 Riccati 방정식(CARE, Continuous Algebraic Riccati Equation)**

```
Aᵀ P + P A − P B R⁻¹ Bᵀ P + Q = 0            (★ CARE)
```

의 *안정화 해*. 코드: `P = scipy.linalg.solve_continuous_are(A,B,Q,R)`, `K = R⁻¹ Bᵀ P` (`lqr.py:92-93`).
이 `K`가 **비용 J를 최소화하는 유일 최적 피드백**이다 — 매 tick 최적화를 푸는 게 아니라 *행렬 K 하나로
최적성이 닫힌형*으로 들어있다(오프라인 1회 계산 → 런타임 곱셈만).

<a id="s5-3"></a>
### 5.3 제어법칙 (trim feed-forward + 오차 피드백)
실제 적용(`lqr.py: command`):

```
u = u₀ − K (x − x*)
```

- `u₀`: 평형 입력(feed-forward) — "그 비행상태를 유지하는 데 필요한 기본 조종". 이게 있어 *오차가
  0일 때 평형 입력*이 그대로 나간다.
- `−K(x − x*)`: 상태가 기준 `x*`에서 벗어난 만큼 *비례·결합 보정*. (`x*`는 외측 루프가 만든
  목표 자세, [§9](#s9).)
- 마지막에 입력 포화 clamp: throttle∈[0,1], 조종면∈[−1,1].

<a id="s5-4"></a>
### 5.4 Q, R을 사람이 손으로 안 찍는다 — Bryson's rule
`Q,R`의 대각값은 **Bryson의 규칙(Bryson's rule)**으로 정한다 — *"허용 최대오차의 역제곱"*:

```
Q[i] = 1 / (xᵢ 최대허용오차)²,     R[j] = 1 / (uⱼ 최대허용사용)²
```

각 상태/입력을 "그 양의 허용범위로 정규화"하는 물리적 의미라, 임의 튜닝이 아니다(`lqr.py:41`,
`DEFAULT_Q/R`). 예: θ 허용오차 5°→`Q[θ]=1/0.087²`, 항법 h·ψ는 *내측이 안 좇으므로* 매우 느슨(≈0).
출처: Bryson & Ho, *Applied Optimal Control* / Stevens & Lewis [§6](#s6).

<a id="s6"></a>
## 6. 안정성 보장 — 수리 증명

"선형으로 풀면 정말 안정한가?"에 대한 답. **세 겹**으로 보장된다.

<a id="s6-1"></a>
### 6.1 정리 (LQR 안정성)
> **정리.** `Q ≥ 0`, `R > 0`이고 `(A,B)`가 *가제어(stabilizable)*, `(A, Q^{1/2})`가 *가관측
> (detectable)*이면, CARE는 *유일한* 대칭 양반정 안정화 해 `P ≥ 0`를 가지며, 닫힘루프
> `A_cl = A − BK` (`K=R⁻¹BᵀP`)의 **모든 고유값이 좌반평면(Re<0)** 이다 — 즉 **점근 안정(Hurwitz)**.

(가제어=불안정 모드를 입력으로 제어 가능, 가관측=불안정 모드가 비용에 보임. F-16의 종·횡 모드는
조종면으로 제어가능하고 Q에 가중되므로 두 조건 충족.) 출처: Anderson & Moore, *Optimal Control:
Linear Quadratic Methods*, Thm 3.7; Stevens & Lewis [§5](#s5).

<a id="s6-2"></a>
### 6.2 Lyapunov 증명 (왜 안정한가)
**Lyapunov 함수**(에너지 같은 음이 아닌 함수가 시간에 따라 줄면 안정) 후보로 Riccati 해를 쓴다:

```
V(δx) = δxᵀ P δx ≥ 0        (P>0이면 양정 — 유효한 Lyapunov 후보)
```

닫힘루프 `δẋ = A_cl δx` 를 따라 시간미분하면:

```
V̇ = δxᵀ (A_clᵀ P + P A_cl) δx
```

CARE와 `K=R⁻¹BᵀP`를 대입해 정리하면 (대칭성 이용) **항등식**

```
A_clᵀ P + P A_cl = −( Q + Kᵀ R K )            (★ Lyapunov 항등식)
```

가 성립한다. 따라서

```
V̇ = − δxᵀ ( Q + Kᵀ R K ) δx ≤ 0
```

`Q≥0, KᵀRK≥0`이라 `V̇≤0`, 그리고 `Q+KᵀRK>0`(가관측성)이면 `V̇<0` — **V가 단조 감소 → δx→0**.
즉 *어떤 작은 이탈이든 평형으로 점근 복귀*함이 증명된다. (이 `−(Q+KᵀRK)` 항등식 유도는 [부록 A](#apx-a).)

<a id="s6-3"></a>
### 6.3 수치 검증 (코드가 매 점에서 확인)
이론에 더해, 코드는 **실제로** 닫힘루프 고유값을 계산해 전부 LHP인지 검사한다:

```python
cl_ev = np.linalg.eigvals(A - B @ K)
self.stable = bool(np.all(cl_ev.real < 0))      # lqr.py:118-119
```

빌드 로그가 9개(3 alt × 3 vc) 운영점 전부 `stable=True`, 가장 느린 고유값(지배 시정수)을 출력한다
(예: `slowest_cl_ev=-9.87,-6.27`). **정리(6.1) + Lyapunov(6.2) + 수치검증(6.3)** 세 겹으로 안정 보장.

## 7. Structured LQR — 종·횡 교차결합 제거

**문제.** 최적 `K`는 일반적으로 *꽉 찬* 행렬이라, F-16 동역학의 종·횡 결합 때문에 "pitch 오차 →
aileron 명령", "bank 오차 → elevator 명령" 같은 **교차 게인**이 생긴다. 이를 그대로 두면 실측상
*pitch 오차가 aileron을 떨고 bank 오차가 elevator를 떠는* 진동·불안정이 났다.

**해법(structured/decentralized LQR).** 물리적으로 elevator·throttle은 *종(pitch/speed)* 전담,
aileron·rudder는 *횡(roll/yaw)* 전담이다. 그래서 `K`의 **종↔횡 교차 블록을 0으로** 강제한다
(`lqr.py:108-115`): elevator·throttle 행의 횡 상태 열 = 0, aileron·rudder 행의 종 상태 열 = 0.

**대가와 정당성.** 이는 *제약 LQR*이라 엄밀 최적은 아니다(약간의 최적성 손실). 그러나 [§6.3](#s6-3)의
**고유값 검증을 통과**(여전히 Hurwitz)하고 실측 진동이 사라지므로, *실용 안정성*을 위한 합리적
trade-off다. 출처: Wie & Bernstein (1992) 분리설계가 강건성에 유리.

## 8. Gain Scheduling — 포락선 보간

[§3.2](#s3-2)의 구현(`GainScheduledLQR`).
- **격자**: alt ∈ {5k, 15k, 25k} ft × vc ∈ {250, 350, 450} kts = **9 운영점**. 각 점에서 [§4](#s4)–6을 풀어
  `(K, x₀, u₀)`를 저장.
- **런타임 보간**: 현재 (h, V)에 인접한 4개 격자점의 `K, x₀, u₀`를 **쌍선형(bilinear) 보간**
  (`_interp_K`). V는 fps→kts 변환 후 인덱싱. 포락선 밖은 경계로 clamp.
- **정당성(준-LPV).** 인접 평형의 `A,B`가 매끄럽게 변하므로 게인도 매끄럽게 변한다고 보고
  보간한다. 스케줄 변수(h,V)가 *충분히 느리게* 변하면(자세 동역학보다 느림 — [§1](#s1)의 시간척도 분리)
  각 순간을 "거의 그 국소 LTI"로 다뤄도 안정성이 유지된다는 게 준-LPV의 근거.

<a id="s9"></a>
## 9. Cascade — setpoint → x*(상태) → u 전 과정

여기가 "setpoint이 어떻게 상태 x로, 다시 u로 가는가"의 핵심. cascade는 **외측 루프(느린 항법) +
내측 LQR(빠른 자세)** 의 2단(`autopilot.py: step`). 외측이 *내측의 기준 상태 x\**를 만든다.

<a id="s9-0"></a>
### 9.0 한 그림
```
setpoint (ψ*, h*, V*)
   │
   ├─[외측 PI] 고도   h_err = h − h*  →  θ_cmd  (피치 목표)
   ├─[외측 PI] 속도   V_err = V − V*  →  throttle 보정
   ├─[외측 P + 협조선회] ψ_err = ψ − ψ*  →  ψ̇_cmd  →  φ_cmd  (롤 목표)
   │
   ▼  기준 상태 구성
 x* = (현재 x 복사)  단  x*[θ]=θ_cmd,  x*[φ]=φ_cmd     ← 자세만 목표로 교체, 나머지 오차 0
   │
   ▼  내측 LQR
 u = u₀ − K (x − x*)        →  throttle override(속도PI) → clamp
```

<a id="s9-1"></a>
### 9.1 외측 — 고도 PI → θ_cmd (종)
고도 오차를 *피치각 목표*로 바꾼다 (높으면 기수 내리고, 낮으면 든다):

```
θ_cmd = −( K_Ph · h_err + K_Ih · ∫h_err dt ),   h_err = h − h*       (±θ_max 포화)
```

PI(비례+적분): 적분항이 정상상태 고도 오차를 0으로(steady-state error 제거). 적분 windup 방지로
적분값 상한.

<a id="s9-2"></a>
### 9.2 외측 — 속도 PI → throttle (종)
```
thr = u₀[thr] − ( K_Pv · V_err + K_Iv · ∫V_err dt ),   V_err = V − V*
```
이 `thr`은 LQR 출력의 throttle 채널을 *override*한다(속도는 외측이 전담).

<a id="s9-3"></a>
### 9.3 외측 — heading P + 협조선회 → φ_cmd (횡)  ★ 핵심 유도
heading은 *직접* 못 바꾼다 — 항공기는 **뱅크(bank)해서 돈다(bank-to-turn)**. 그래서 heading 오차를
*롤각 목표 φ_cmd*로 번역해야 한다. 두 단계:

**(1) heading 오차 → 원하는 선회율 ψ̇_cmd** (비례 제어, 최대 선회율로 포화):
```
ψ̇_cmd = clamp( K_Pψ · ψ_err, ±ψ̇_max ),   ψ_err = wrap(ψ − ψ*) ∈ [−π,π]
```

**(2) 원하는 선회율 → 롤각** (협조선회 공식). *유도*: 옆미끄럼 없는(coordinated) 정상 선회에서,
양력 L의 수평성분이 구심력을, 수직성분이 중력을 담당한다:
```
수평:  L sin φ = m V ψ̇        수직:  L cos φ = m g
나누면:  tan φ = V ψ̇ / g   ⇒   φ = atan( V ψ̇ / g )            (★ 협조선회 공식)
```
따라서 원하는 ψ̇_cmd에 필요한 롤각:
```
φ_cmd = − atan( ψ̇_cmd · V / g )      (±φ_max 포화; 부호는 heading 증가=우선회 규약)
```
- 물리적 의미: *더 빨리 돌려면(ψ̇↑) 더 눕혀야(φ↑)* 하고, *빠를수록(V↑) 같은 선회율에 더 눕혀야*
  한다 — 식이 정확히 그렇게 말한다. (V는 실속 이하 클램프로 0나눗셈·발산 방지.)
- 출처: Nelson, *Flight Stability and Automatic Control* [§4](#s4) (coordinated turn).

<a id="s9-4"></a>
### 9.4 기준 상태 x* 구성 — "setpoint → x"
외측이 만든 자세 목표(θ_cmd, φ_cmd)를 **내측 LQR의 기준 상태 x\***로 조립한다(`autopilot.py:229-231`):
```
x* = x.copy()        # 현재 상태 복사 → "나머지 상태의 오차는 0"으로 둠
x*[θ] = θ_cmd        # 종 자세 목표만 교체
x*[φ] = φ_cmd        # 횡 자세 목표만 교체
```
- **왜 "현재 복사 후 θ,φ만 교체"인가**: 내측 LQR은 *자세 안정*만 책임진다. 나머지 상태(V,q,β,p,r,…)는
  "지금 값을 유지(오차 0)"가 목표이므로 `x*=x`로 두고, *바꾸고 싶은 자세 2개*만 목표로 둔다. h·ψ는
  Q에서 ≈0이라 LQR이 무시 → 외측이 θ_cmd·φ_cmd로 간접 통제. **이게 cascade가 안정한 비결**: 내측은
  태도만, 항법은 외측이.

<a id="s9-5"></a>
### 9.5 내측 — LQR이 u 산출 "x → u"
이제 [§5.3](#s5-3) 그대로:
```
u = u₀ − K (x − x*)
```
`x−x*`는 (대부분 0이고) θ·φ 채널에 *자세 오차*가 들어있다. K가 이를 elevator(종)·aileron/rudder(횡)
명령으로 *최적·안정적으로* 사상한다. 마지막에 [§9.2](#s9-2)의 throttle override + 포화 clamp.

> **전체 한 줄**: *setpoint → (외측 PI/P가) 자세목표 θ_cmd·φ_cmd → x*에 심음 → (내측 LQR이)
> u = u₀ − K(x−x*) → JSBSim.* 느린 항법은 외측이, 빠른 자세는 내측이 — 둘 다 안정 보장.

## 10. 전체 파이프라인 (한 흐름, 단위 명시)

```
[상위 의사결정] Tactic → guidance → Setpoint(ψ*[°], h*[ft], V*[kts])
        │
        ▼  (autopilot.step, 20 Hz)
  단위변환:  ψ*→rad,  V*→trim TAS(fps)  (CAS/TAS 혼동 방지)
        │
  외측 PI(고도):   h_err=x[h]−h*      → θ_cmd[rad]   (±15°)
  외측 PI(속도):   V_err=x[V]−V*(fps) → thr_cmd
  외측 P+협조선회: ψ_err=wrap(x[ψ]−ψ*) → ψ̇_cmd → φ_cmd[rad] (±78°=4.8G)
        │
  x* = x;  x*[θ]=θ_cmd;  x*[φ]=φ_cmd
        │
  게인 스케줄:  (x[h], x[V]) → 인접4점 보간 → (K, x₀, u₀)
        │
  내측 LQR:   u = u₀ − K (x − x*)
  override:   u[throttle] = thr_cmd
  포화:        u[0]∈[0,1], u[1:]∈[−1,1]
        │
        ▼
  u = [throttle, elevator, aileron, rudder]  → JSBSim plant → ẋ=f(x,u) → 다음 x
```

(상위가 준 V*는 *trim TAS* 기준으로 해석된다 — kts를 직접 fps로 바꾸지 않고 운영점 trim의 TAS를
씀. 메모리 [[new-engine-math-units]]의 CAS/TAS 규약.)

## 11. 정직한 한계와 가정 (연구적 서술)

| # | 가정/한계 | 영향 | 완화 |
|---|---|---|---|
| L1 | **국소 선형 근사** | 평형에서 *크게* 벗어난 과기동(예: 깊은 실속·고α)에서는 A,B가 부정확 | 게인 스케줄 + 보수적 포화(±78° bank, α가중 Q). 단 극한 기동은 보장 밖 |
| L2 | **유한차분 야코비안** | δ·n_steps 선택에 민감([§4.2](#s4-2) 부호버그 이력) | 중앙차분 + n_steps=10 검증, 고전모드 대조([§4.3](#s4-3)) |
| L3 | **구조적 K(종횡분리)** | 엄밀 최적 아님(최적성 손실) | 고유값 검증 통과 + 실측 진동 제거([§7](#s7)) |
| L4 | **게인 스케줄 보간** | 격자 사이·빠른 (h,V) 변화 시 준-LPV 가정 약화 | 격자 9점, 스케줄 변수가 자세보다 느림(시간척도 분리) |
| L5 | **외측 선형 PI/P** | 큰 setpoint 계단에서 포화·windup | 포화 클램프 + 적분 windup 상한 |
| L6 | **무한구간·시불변 LQR** | 각 점은 LTI 가정 | 매 점 trim+재선형화로 점별 LTI 보장 |

→ **핵심 정직성**: 이 제어기는 *평형 부근에서 증명가능하게 안정·최적*이다. 극한 BFM 과기동은
선형 보장의 *밖*이지만, 포화·게인스케줄·구조화로 실용 안정 범위를 넓혔고, **9 운영점 전부에서
수치 안정 검증**을 통과한다.

<a id="s12"></a>
## 12. LQR이 1:1 dogfight를 풀기에 적합한가 — 역할의 정확한 구분

이 질문엔 **개념을 먼저 분리**해야 정직히 답할 수 있다.

**핵심 구분: "게임을 푸는 것" ≠ "기동을 실행하는 것".**
- 1:1 dogfight는 본질적으로 **미분 게임(differential game)** — *두 적대자*의 추격-회피
  (pursuit-evasion)다. "어떤 기동을, 언제" 는 *상대의 최적 대응*까지 고려하는 게임이론(HJI
  value function, minimax, 강화학습)의 영역이다. **LQR은 이 게임을 풀지 않는다 — 풀 수도 없다**
  (단일 에이전트 조절기이지 게임 해가 아님).
- LQR의 **역할은 저수준 *기동 실행*** 이다: 상위가 "이 자세·궤적으로 가라(setpoint)"고 하면,
  그것을 *정밀·안정·신속하게* 추종한다.

**그럼 dogfight의 어디에 LQR이 적합한가 (계층).**
```
[게임 지능]  상황 분류 → 어떤 BFM 기동(추격/요요/선회)?   ← 게임이론/정책 (LQR 아님)
     │ setpoint (ψ*, h*, V*)
[실행]       LQR autopilot → 조종면 u                       ← ★ LQR의 자리
     │ u
[물리]       JSBSim F-16
```
BFM 기동(pure pursuit, high yoyo, one-circle…)은 결국 *시간에 따른 setpoint 시퀀스*로 환원되고,
LQR이 그 시퀀스를 충실히 실행한다. 즉 **dogfight 지능은 위층(상황 독립 정책,
[방법론 문서](12_offline_policy.md))에, 기동 실행은 LQR에** — 역할이 다르다.

**적합성 판정 (정직).**
- ✅ **자기 계층엔 매우 적합**: 기동 실행은 *정밀·안정·신속·증명가능*해야 하는데, LQR이 정확히
  그것을 준다([§6](#s6) 안정 보장, [§5](#s5) 최적성, μs 실행). RNN 블랙박스 실행을 투명 LQR로 대체한 것이 옳다.
- ❌ **"LQR으로 dogfight를 푼다"는 범주 오류**: LQR을 게임 해로 쓰려는 시도는 적의 반응을 못 담아
  실패한다. 본 프로젝트는 *이 오류를 피해* — 게임은 위층 정책이, 실행은 LQR이 — 명확히 분리했다.
- ⚠️ **연결의 한계**: LQR이 추종하는 setpoint가 *기동학적으로 도달 가능*해야 한다. 상위가 비현실적
  기동(과도한 선회율)을 요구하면 포화로 잘린다 — 그래서 위층이 포락선(±78° bank=4.8G 등)을 알아야
  한다. 실측상 *제어는 물리한계까지 다 쓰고도* 일부 BFM 기하를 못 만든 사례가 있다(이는 LQR 결함이
  아니라 *기체 성능·기하의 한계*).

> **[§12](#s12) 한 줄**: *LQR은 dogfight를 "푸는" 도구가 아니라 "실행하는" 도구다. 게임은 위층 정책이 풀고,
> LQR은 그 결정을 정밀·안정하게 조종면으로 옮긴다 — 그 역할엔 최적이다.*

<a id="s13"></a>
## 13. LQR을 "제대로·완전하게" 썼는가 — 정직한 사용 점검

LQR의 *어느 부분을 교과서대로 썼고, 어디서 공학적으로 벗어났으며, 무엇을 의도적으로 생략했는지*를
숨김없이 점검한다.

<a id="s13-1"></a>
### 13.1 교과서대로 (정확·완전)
| 요소 | 상태 |
|---|---|
| CARE로 최적 게인 `K=R⁻¹BᵀP` | ✅ scipy `solve_continuous_are` — 정확한 최적해 |
| 안정성 보장 ([§6](#s6) 정리+Lyapunov+수치) | ✅ 9점 전부 Hurwitz 검증 |
| **완전상태 피드백** | ✅ JSBSim에서 10상태 전부 *직접 관측*(완전관측) → **관측기/LQG 불필요**. 이건 생략이 아니라 *완전*: 추정 오차원이 없음 |
| Bryson Q/R | ✅ 임의 튜닝 아닌 물리적 정규화 |

<a id="s13-2"></a>
### 13.2 공학적 변형 (벗어남 — 근거 있음)
| 변형 | 무엇을 잃나 | 왜 그래도 정당한가 |
|---|---|---|
| **Structured K** (종횡 교차 0) | *엄밀* 최적성 + 고전 LQR이 보장하는 *마진 정리는 unstructured에만* 엄밀 적용 | 실측 진동 제거 + 수치 고유값 검증 통과([§7](#s7)). 정리 대신 *측정된 안정*을 택함 |
| **추종을 feed-forward + 외측 PI**로 | `x*`(θ_cmd,φ_cmd)가 *엄밀 평형이 아님* → 미세 정상상태 offset | 외측 PI의 *적분항*이 그 offset을 0으로 흡수([§9.1](#s9-1)). 내측 LQI 대신 cascade 적분 — 표준 설계 |
| **게인 스케줄(보간)** | 정식 LPV 합성이 아닌 *보간* → 전역 보장은 slowly-varying 가정 하 | 격자 9점 + 시간척도 분리([§3.5](#s3-5), [§8](#s8)). 항공제어 표준 실무 |

<a id="s13-3"></a>
### 13.3 의도적 생략 (안 쓴 것 — 그게 맞는가)
| 안 쓴 것 | 판단 |
|---|---|
| **LQG / Kalman 관측기** | ✅ 옳음 — 완전관측이라 추정 불필요 |
| **내측 LQI(적분증강 LQR)** | ✅ 허용 — 적분은 외측 PI가 담당(cascade) |
| **정식 강건합성(H∞/μ)** | ⚠️ 미사용 — LQR *내재 마진* + structured 설계의 *측정 안정*에 의존. 큰 모델오차 강건 보장은 한계 |
| **참조궤적 feed-forward(미분항)** | ⚠️ 미사용 — setpoint를 *계단*으로 처리. 빠른 setpoint 변화 시 추종지연(외측 P 게인으로 일부 보완) |

<a id="s13-4"></a>
### 13.4 판정 (정직)
- **핵심(최적 게인·안정성·완전상태)은 교과서대로 정확·완전**하게 썼다.
- 다만 **structured·cascade추종·스케줄링**의 변형 때문에, 정확히는 *"단일 교과서 LQR"이 아니라
  **게인 스케줄 cascade 오토파일럿(그 내핵이 LQR)** "* 이다. 모든 변형엔 근거와 검증이 있다.
- ★ "완전하게 썼나?"의 가장 정직한 답: **조절기(regulator)로서의 LQR은 완전·정확히 썼다. 추종·강건·
  스케줄링은 *cascade 설계로 보완*했고, 정식 강건합성은 의식적으로 생략(향후 보강 여지).**

<a id="s14"></a>
## 14. 무엇이 *보장*되고 무엇이 *backup* 하는가 (안전·강건)

> (질문 "back duty 보장" 을 *backup/안전 fallback duty의 보장* + *강건 마진* 으로 해석. 다른 의미면
> 알려주면 보강.)

<a id="s14-1"></a>
### 14.1 *증명으로* 보장되는 것
1. **국소 점근 안정** — 각 운영점에서 [§6](#s6)(정리+Lyapunov)·[§3.4](#s3-4)(비선형 전이)로 *증명*. 9점 수치검증.
2. **고전 LQR 마진** — *unstructured* 채널에 한해 LQR은 **게인여유 ≥6 dB(상방 ∞)·위상여유 ≥60°**
   를 *정리로* 보장(Safonov-Athans). 코드의 `gain_margin_db()`가 종 채널 마진을 출력한다.
   ⚠️ structured 채널은 이 정리 밖 → [§6.3](#s6-3) 수치검증으로 대체.
3. **입력 포화 처리** — throttle∈[0,1], 조종면∈[−1,1] clamp로 *물리 한계 초과 명령 방지*.
4. **결정론적 재현성** — 같은 상태 → 같은 u (RNG 없음). 검증·인증에 유리.

<a id="s14-2"></a>
### 14.2 *backup(안전 fallback) duty* — 보장되는가
- **Safety 우선 override (보장됨)**: 의사결정층에 **Hard Deck 안전 분기**가 최우선으로 박혀 있다
  — `alt < 2500 ft` 면 정책·LQR 추종을 *무조건 중단*하고 `CLIMB`(wings-level 최대 상승)로 전환
  ([tree_policy.py](../../new_match_engine/bt/tree_policy.py)). 즉 *"무슨 일이 있어도 땅에는 안 박는다"*
  는 backup duty가 **상시 보장**된다.
- **포화·각도 한계 (graceful degradation)**: α 가중 Q(실속 방지)·±78° bank 포화가 *극한 기동에서도
  안전 자세 범위*를 강제한다.
- **운영점 clamp**: 포락선 밖 (h,V)는 경계 게인으로 clamp → *정의되지 않은 외삽 방지*.

<a id="s14-3"></a>
### 14.3 *보장되지 않는* 것 (정직)
- **선형 보장 영역 밖**: 깊은 실속·post-stall·초고받음각 과기동은 [§3](#s3)의 국소 선형 보장 *밖*이다 —
  Lyapunov 간접법의 끌림영역을 벗어나면 안정 증명이 끊긴다. 이때는 [§14.2](#s14-2)의 *backup(CLIMB/포화)* 가
  *안전*은 지키나 *성능(추종)* 은 보장 못 함.
- **큰 모델오차 강건성**: 정식 강건합성을 안 했으므로([§13.3](#s13-3)), 모델/공력 큰 불확실성에 대한 *정량
  강건 보장*은 없다 — LQR 내재 마진에 의존.
- **게인 스케줄 급변**: slowly-varying 가정이 깨지는 급격한 포락선 횡단의 전역 안정은 미보장([§3.5](#s3-5)).

> **[§14](#s14) 한 줄**: *증명되는 보장 = (운영점별) 국소 점근 안정 + 고전 LQR 마진 + 포화. backup duty =
> Hard Deck 안전 override가 "땅에 안 박음"을 상시 보장. 단 극한 기동·큰 모델오차의 성능은 보장 밖
> 이며, 그땐 안전 fallback이 받는다 — 이것이 정직한 보장 경계다.*

## 15. 이론적 근거(문헌)와 고기동 fidelity — 정직한 검증

> 두 질문에 정직히 답한다: **(1) 국소 선형화·게인스케줄에 *증명된 이론적 근거*가 있는가? (2) 그게
> *고기동*에서도 fidelity가 확인되었는가?** 아래는 *실제 문헌*으로 검증한 것이며, open-access는 링크를 단다.

<a id="s15-1"></a>
### 15.1 이론적 근거 — 있다 (각 주장 → 실제 문헌)

| "선형 Hurwitz ⇒ 비선형 국소 점근 안정" ([§3.4](#s3-4)) | **Lyapunov 간접법** — Khalil, *Nonlinear Systems* 3rd, **Thm 4.7** | 교재(공개 강의노트 다수) |

★ **핵심 근거 — Shamma & Athans (1990)**: 게인스케줄 제어가 *언제* 전역적으로 안정·강건한지를
**정리로 증명**한 논문. 결론이 우리 [§3.5](#s3-5)·[§8](#s8)의 단서와 *정확히 일치*한다 — 스케줄 변수가

즉 우리 방법의 *유효 조건*이 문헌으로 형식화되어 있다.

<a id="s15-2"></a>
### 15.2 고기동 fidelity — ★ 정직: *확인되지 않았고, 오히려 열화가 문헌에 기록됨*
가장 정직해야 할 부분이다. **국소 선형화 + 게인스케줄의 fidelity는 고기동(고받음각·고각속도)에서
*확인되지 않았다* — 문헌은 그 반대(성능 *저하*)를 보고한다.**

- Snell, Enns & Garrard (1992), "Nonlinear Inversion Flight Control for a Supermaneuverable
  Aircraft" (J. Guidance & NTRS 무료): *"항공기 동역학은 고받음각에서 강한 비선형인데, 게인스케줄
  비행제어는 본질적으로 선형 기법으로 설계되어 **고받음각·고각속도에서 성능이 저하**된다"* 고 명시.
  비선형 동역학 역변환(NDI)이 게인스케줄 선형보다 *전 포락선에서 우월*함을 보였다.
- NASA **HARV(High-Alpha Research Vehicle)** 고받음각 비행시험 계보가 바로 이 한계 때문에 등장 —
  선형 게인스케줄을 NDI/INDI(비선형) 로 대체.
- → **결론(정직)**: *고기동은 선형 보장([§3](#s3) 끌림영역) 밖이며, 우리 방법으로 fidelity가 검증된 바
  없다.* 이는 우리 한계([§11](#s11) L1, [§14.3](#s14-3))와 **문헌이 일치**한다. 고기동을 제대로 다루려면 NDI/INDI
  같은 *비선형* 제어가 표준이다.

<a id="s15-3"></a>
### 15.3 두 fidelity를 구분하라 — 플랜트 vs 제어기
혼동을 막기 위해:
- **플랜트(JSBSim) fidelity**: F-16 고받음각 공력은 NASA TP-1538(Nguyen 1979) 등 *고받음각 풍동·
  비행 데이터*에 기반한 표준 모델이다 — *극한 post-stall 외*에는 신뢰. (우리 *시뮬*의 물리는 합리적.)
- **제어기(게인스케줄 LQR) fidelity**: 위 [§15.2](#s15-2)대로 *고기동에선 보장 밖*. 즉 "물리는 그럴듯해도,
  *선형 제어기가 그 물리를 고기동에서 잘 제어한다*는 보장은 없다."
- 우리 구현의 실측 정합성(§D.3)도 이를 뒷받침: 내측 LQR은 *정상 자세 부근*에서 증명대로 동작하고,
  큰 기동(heading 전환)은 외측 cascade가, 극한·deck 위험은 *안전 override*([§14.2](#s14-2))가 받는다.

<a id="s15-4"></a>
### 15.4 그래서 우리 선택은 정당한가
- **정당함 (조건부)**: 본 프로젝트의 LQR은 *정상~중간 기동의 정밀·안정 실행기*다([§12](#s12)). 그 영역은
  Shamma–Athans·Lyapunov 간접법으로 *증명된 근거*가 있다. 고기동 격투 *지능*은 위층 정책이 풀고,
  극한은 안전 fallback이 받는다 — *각 계층이 제 보장 범위 안에서* 작동.
- **한계 명시**: 만약 *제어기 자체*로 고받음각·post-stall 초기동을 다뤄야 한다면, 본 선형 방법은
  부적합하며 **NDI/INDI(비선형) 또는 LPV 합성으로 확장**이 정공법이다(향후 과제).

<a id="s16"></a>
## 16. 비판적 점검 — "결국 PI 아닌가?" / "국소화 보장이 진짜인가?"

> 정당한 의심이다. *"국소 선형화의 LQR 해를 써서 사실상 PI 제어를 하는 것이고, 그게 비선형을
> 국소로 잘랐다고 진짜 보장되는가?"* — 두 질문을 분리해 정직하게 답한다.

<a id="s16-1"></a>
### 16.1 (A) LQR ≟ PI — 무엇이 같고 무엇이 다른가
**같은 점(인정).** 최종 실행 형태는 *둘 다 선형 피드백*이다. 게다가 **외측 루프는 진짜로 PI/P**다:
고도·속도는 *PI*(비례+적분), heading은 *P*([§9](#s9)). 그러니 "cascade가 PI처럼 느껴진다"는 *맞는 관찰*이다.

**다른 점(핵심).** 차이는 *내측 루프*와 *게인을 얻는 방식*에 있다:
1. **MIMO vs SISO.** PI는 한 번에 *한 입출력 쌍*을 보고 나머지 결합을 외란으로 친다. 내측 LQR은
   *10상태 × 4입력 결합계 전체*를 한꺼번에 본다 — `K`는 4×10 행렬로, "β가 rudder와 aileron에 동시에
   어떻게" 같은 **교차 게인 40개를 (A,B)로부터 최적·일관되게** 정한다. scalar PI 튜닝으론 이 40게인을
   안정·최적 보장으로 못 맞춘다.
2. **내측엔 적분이 없다.** 내측 LQR은 `u=u₀−K(x−x*)` — *순수 상태비례*다. 즉 엄밀히는 "PI"가 아니라
   **다변수 최적 *P* 피드백**. 적분("I")은 *필요한 곳에만* 외측에 둔다([§16.2](#s16-2)).
3. **게인이 *선형화 모델*에서 나온다.** PI 게인은 손튜닝이지만, LQR 게인은 *그 운영점의 (A,B)*를
   CARE로 풀어 나온다 — **게인이 국소 동역학을 *인코딩*** 한다. 이게 "그냥 PI"와 갈리는 지점이다.

**적분을 *어디에* 두는가 — 설계의 정밀함.** 왜 고도·속도엔 적분(PI), heading엔 P인가?
- 고도·속도: 정상상태 오차를 0으로 만들려면 *적분*이 필요(외란·모델오차 보상) → **PI**.
- heading: *plant가 이미 적분기*다 — heading은 선회율의 적분(ψ=∫ψ̇). 그래서 P만으로도 계단입력에
  정상오차 0(type-1 시스템). 불필요한 적분을 안 넣는다 → **P**. *적분을 물리가 요구하는 자리에만* 둠.

> **(A) 정직한 답**: *구조적으로는 "고급 선형 피드백"이라 PI/P 계열로 볼 수 있다 — 인정.* 그러나
> 내측은 *(A,B)에서 유도된 다변수 최적 P*이고 적분은 *필요한 채널에만* 배치된다. LQR의 값어치는
> *실행 형태*가 PI와 다르다는 게 아니라, **게인을 선형화 모델로부터 최적·보장적으로 *유도*** 한다는
> 데 있다. "손으로 찍은 PI"와 "(A,B)로 푼 LQR"은 *같은 형태, 다른 출처와 보장*이다.

<a id="s16-2"></a>
### 16.2 (B) "비선형을 국소로 잘랐다" — 무엇이 *증명*되고 무엇이 *가정*인가
여기서 가장 정직해야 한다. 보장은 **층마다 다르다.**

**증명되는 것 (내측 LQR @ 한 trim).**
- 내측 LQR이 만든 닫힘루프 선형화 `A−BK`가 **Hurwitz**([§6](#s6) 검증) → **Lyapunov 간접법([§3.4](#s3-4))** →
  *그 trim은 비선형 플랜트의 **국소 점근 안정** 평형*. 이건 **진짜 증명**이고 9점 수치검증.
- ★ 미묘하지만 중요: 이 국소 보장은 **"LQR이라서"가 아니라 "닫힘루프 선형화가 Hurwitz라서"** 다.
  PI든 LQR이든 `A−BK`를 Hurwitz로 만들면 *동일한* 국소 비선형 보장을 받는다. **LQR은 그 Hurwitz
  게인을 *최적·체계적으로 구성*하는 방법**일 뿐 — 보장의 원천은 Lyapunov 간접법이다. (그래서 (A)의
  "PI 같다"는 느낌과 (B)의 "보장 있다"는 *모순이 아니다*: 보장은 *형태*가 아니라 *Hurwitz성*에서 온다.)

**가정에 기대는 것 (전체 cascade + 스케줄링).**
- 우리가 *수치로 검증*한 건 **내측 `A−BK`**(각 격자점)다. **전체 cascade**(외측 PI *적분기 상태*까지
  포함한 증강계 + 스케줄 `K(h,V)`)의 비선형 안정은 *단일 정리로 안 덮인다.*
- 그게 성립하려면: (a) 내측 국소보장 — *있음(증명)*, (b) **시간척도 분리** — 외측(항법)이 내측(자세)보다
  느림([§1](#s1)) → 증강계가 분리 가능, (c) **Shamma–Athans slowly-varying**([§15.1](#s15-1)) — 스케줄 변수가 느리게
  변할 것. (b)(c)는 우리가 *설계·가정*으로 충족하나, **전 cascade end-to-end 형식증명은 없다(정직).**

> **(B) 정직한 답**: *"비선형을 국소로 잘랐다"는 **내측 LQR 차원에선 정리로 증명**된다(Lyapunov 간접법,
> 9점 검증). 다만 **외측 PI·게인스케줄까지 포함한 전체의 전역 안정은 시간척도 분리·slowly-varying
> *가정* 위에서만** 성립하며, 단일 end-to-end 증명은 *하지 않았다*. 즉 "국소 절단"은 *국소적으론
> 증명, 전역 스티칭은 표준 가정*이다 — 이것이 정확한 보장 경계다.* (이 경계는 [§15.1](#s15-1) Shamma–Athans가
> 말하는 조건과 동일하다.)*

<a id="s16-3"></a>
### 16.3 한 문단 요약
*맞다 — 실행 형태만 보면 다변수 PI/P다.* 그러나 ① 게인이 *(A,B) 선형화에서 최적 유도*되고
(손튜닝 PI와 다른 점), ② 그 결과 `A−BK`가 Hurwitz라 **Lyapunov 간접법으로 *그 평형의 국소 비선형
안정이 증명*** 된다. "국소로 잘랐다"의 보장은 *내측에서 진짜*이고, 전역(cascade+스케줄)은 *표준
가정*에 의존한다. LQR의 본질 기여는 "PI와 다른 마법"이 아니라 **"국소 선형화로부터 안정·최적 게인을
체계적으로 *구성하고 그 국소 보장을 정리로 받는다*"** 는 데 있다.

<a id="apx-a"></a>
## [부록 A](#apx-a). Lyapunov 항등식 유도 ([§6.2](#s6-2))

`A_cl = A − BK`, `K = R⁻¹BᵀP`, `P=Pᵀ`. 전개:
```
A_clᵀP + P A_cl = (A−BK)ᵀP + P(A−BK)
                = AᵀP + PA − KᵀBᵀP − PBK
```
CARE에서 `AᵀP + PA = PBR⁻¹BᵀP − Q`. 또 `PBK = PBR⁻¹BᵀP`, 그리고 대칭성으로
`KᵀBᵀP = (R⁻¹BᵀP)ᵀBᵀP = PBR⁻¹BᵀP = PBK`. 대입:
```
= (PBR⁻¹BᵀP − Q) − PBK − PBK
= PBR⁻¹BᵀP − Q − 2 PBR⁻¹BᵀP
= −Q − PBR⁻¹BᵀP
= −( Q + KᵀRK )            ∵ KᵀRK = (R⁻¹BᵀP)ᵀR(R⁻¹BᵀP) = PBR⁻¹BᵀP   ∎
```
