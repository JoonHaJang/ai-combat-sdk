# 15장. 시나리오 실험 — 교범 상황을 코드로

## 학습 목표
이 장을 마치면 다음을 할 수 있다.
- 교범의 추상적 상황을 재현 가능한 실험으로 만드는 방법을 안다.
- 한 시나리오가 어떤 시작 기하로 정의되는지 안다.
- 우리 코드의 spawn 함수가 각 상황을 어떻게 만드는지 안다.
- 거리를 위도와 경도 좌표로 변환하는 방법을 안다.
- 시나리오별 표준 평가 절차와 검증 목표를 설명한다.

이 장은 3장의 이론과 앞선 구현을 잇는 실험대다. 3장이 1대1 dogfight 상황과 해법을 정리했다면,
여기서는 그 상황 하나하나를 AIPILOT이 마주하도록 시작 배치를 만들어 반복 실험한다.

---

## 15.1 왜 시나리오인가

"우리 AIPILOT이 정면 머지를 잘 푸는가" 같은 질문에 답하려면, 정면 머지 상황을 똑같이 여러 번
만들 수 있어야 한다. 시나리오는 교범의 상황을 고정된 시작 배치로 못 박아, 같은 출발에서 반복
실험하게 한다. 결과를 재생 파일과 정량 리포트로 남기면, 그 상황에서 어떤 전술이 언제 나왔고 결과가
어땠는지 분석할 수 있다. 즉 추상적 교리가 측정 가능한 실험이 된다.

---

## 15.2 시나리오의 정의

한 시나리오는 두 기체의 시작 배치다. 다섯 가지로 정해진다. 상대 위치(누가 누구 뒤·앞·옆), 자세각
(aspect), 거리, 속도, 그리고 진행방향 차이다. 이 다섯이 정해지면 3장의 관측값(ATA, AA, HCA, 거리,
closure)이 결정되고, 그것이 곧 교전 국면(공격, 방어, 중립)을 정한다.

코드에서 시나리오는 spawn 함수다. 두 F16Plant 객체를 만들어 위치, 방위, 고도, 속도를 설정하고
초기화한다.

---

## 15.3 구현된 spawn 함수

현재 기준 시작 조건은 중립 빔이다(engine/scenarios.py).

중립 빔(spawn_adt_neutral). 두 기체가 동서로 약 3000피트 떨어져, 한쪽은 남향 한쪽은 북향으로 서로
90도 빔, 정반대 진행한다. 의도된 중립이다. 평가의 표준 출발점이다.

```
   us(서, 남향 ↓)            opp(동, 북향 ↑)
        ●  ────  3000ft  ────  ●
        ↓                       ↑
   서로 90도 빔, anti-parallel = 중립
```

공격(spawn_offensive). 우리가 적의 6시 뒤, 같은 방향으로 일정 거리 앞에 적을 둔다. 곧 공격 위치다.

```
   us(남, 북향 ↑)   ───►   opp(앞, 북향 ↑)
        ●  ──── range ────  ●         (우리가 적 6시 뒤 = 공격)
```

방어(spawn_defensive). 공격의 역으로, 적이 우리 6시 뒤에 있어 우리가 피격 위협을 받는다.

정면(spawn_headon). 두 기체가 마주 보고(한쪽 북향, 한쪽 남향) 일정 거리에서 접근한다. 머지로
이어진다.

좌표 변환. 거리(피트)를 위도·경도(도)로 바꿔 위치를 잡는다. 위도 1도당 피트 환산 상수로 남북
거리를, 위도 60도에서의 경도 압축(코사인 약 0.5)을 보정해 동서 거리를 만든다. 이렇게 하면 "적을
3000피트 뒤에" 같은 명령을 정확한 위경도로 옮길 수 있다.

## 15.4 추가 시나리오

3장의 표에는 위 넷 외에도 선회전과 에너지 상황이 있다. 이들은 시작 기하로 다음과 같이 만든다.

one-circle. 정면 머지에서 두 기체가 같은 방향으로 틀도록 유도되는 근접 시작. 작은 반경 코대코
싸움을 검증한다.

two-circle. 정면 머지에서 분리를 두고 반대 방향으로 틀도록 하는 시작. 코너 속도 선회율 싸움을
검증한다.

고에너지 대 저에너지. 한쪽에 고도나 속도 우위를 부여한 시작. 요요와 에너지 관리, 수직 기동을
검증한다.

익스텐션 추격. 적이 멀리서 직선 가속으로 이탈하는 시작. 수직 추격으로 따라붙기와 무리한 추격
회피를 검증한다.

저고도. 낮은 시작 고도 또는 강제 강하 상황. 안전 상승 우선과 지면 충돌 회피를 검증한다.

이들은 위 네 spawn 함수와 같은 방식(상대 위치·고도·속도·방위 설정)으로 추가한다.

---

## 15.5 표준 평가 절차

모든 시나리오는 같은 절차를 따른다. 시작 배치에서 한 판을 끝까지 돌리고, 세 가지 산출물을 남긴다.
Tacview 재생 파일(.acmi), 정량 리포트(report.txt), 그리고 궤적 그림(plot.png)이다. 리포트에는
시간에 따른 전술 선택, 무장 사용 구역 진입과 피해, 에너지 변화가 담긴다.

```
spawn 함수 → 한 판 실행(300초) → (.acmi 재생 + report.txt + plot.png)
                                  → 전술 타임라인·WEZ·에너지 분석
```

이 절차 덕분에 "이 상황에서 우리 정책이 무엇을, 언제, 왜 했고 결과가 어땠는가"를 매번 같은 형식으로
본다.

## 15.6 무엇을 검증하나

각 시나리오는 3장의 어떤 해법이 실제로 구현되는지를 확인한다.

| 시나리오 | 검증하는 해법(3장) |
|---|---|
| 정면 머지 | one/two-circle 선택, 머지 방향 결정 |
| 중립 빔 | 중립에서 우위 전환 (표준 출발) |
| 공격 추격 | 통제 구역 유지, 추격 형태, 사격 마무리 |
| 방어 | 브레이크 턴, 오버슈트 강요, 시저스 역전 |
| one-circle | 작은 반경 코대코 우위 |
| two-circle | 코너 속도 선회율 우위 |
| 고저 에너지 | 요요, 에너지 관리, 수직 기동 |
| 익스텐션 | 수직 추격, 무리한 추격 회피 |
| 저고도 | 안전 상승 우선 |

이렇게 시나리오는 교범과 구현을 잇는 마지막 고리다. 3장의 상황과 해법이 11장의 정책과 7장의
제어를 통해 실제로 나타나는지를, 재현 가능한 실험으로 확인한다.

## 연습문제
1. 한 시나리오를 정의하는 다섯 가지 시작 요소를 적어라.
2. 중립 빔 시작에서 두 기체의 방위와 거리, 진행방향 관계를 그림으로 그려라.
3. 공격(spawn_offensive)과 방어(spawn_defensive)가 서로 역인 이유를 시작 위치로 설명하라.
4. "적을 3000피트 뒤에" 두려면 거리를 어떻게 위경도로 변환하는가. 위도 60도 보정은 왜 필요한가.
5. one-circle와 two-circle 시나리오의 시작 기하 차이를 적고, 각각 무엇을 검증하는지 쓰라.
